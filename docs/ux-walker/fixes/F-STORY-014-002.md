# F-STORY-014-002 Fix Report

## What Was Wrong

Skill deletion relied on `window.confirm`. The confirmation was outside the app UI, inconsistent with nearby settings flows, and blocked browser automation during the authenticated walk.

## What Changed

- `apps/web/app/settings/skills/skills-section.tsx`
  - Replaced the native confirmation with inline Confirm and Cancel controls on the skill card.
  - Kept the destructive API call behind an explicit second click.

## Verification

- Browser smoke: created `/ux-delete-check`, clicked `Delete /ux-delete-check`, saw inline Confirm/Cancel controls, clicked Confirm, and verified the `No skills yet` empty state returned.
- Tests: `bun test apps/web/app/settings/skills/skills-section.test.ts`.
