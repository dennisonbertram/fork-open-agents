# F-STORY-016-001 Fix Report

## Correction (issue #765)

This report originally claimed the fix below had already shipped. It had not:
neither `getTemplateActionLabel` nor `apps/web/app/loops/loop-create-experience.test.tsx`
existed in the codebase before issue #765. The gallery's "Use this template"
buttons had no per-template accessible name until the #765 fix landed. This
report is corrected to describe what actually shipped, in the commit that
also fixed the templates-and-drafts truth issues tracked in #765.

## What Was Wrong

The loop template gallery rendered repeated `Use this template` buttons. The visible text was fine for sighted users because each button sat inside a card, but assistive technologies saw several identical actions with no template context.

## What Changed (shipped in #765)

- `apps/web/app/loops/loop-create-experience.tsx`
  - Added `getTemplateActionLabel(templateName)` → `"Use <name> template"`.
  - Added per-template `aria-label` values to the template gallery's action buttons while leaving the compact visible "Use this template" label unchanged.
- `apps/web/app/loops/loop-create-experience.test.tsx`
  - New test file (did not exist before #765). Asserts every template button carries a distinct `aria-label` matching `getTemplateActionLabel`, and that no two templates share a label.

## Verification

- Tests: `bun test apps/web/app/loops/loop-create-experience.test.tsx` (new coverage, first real proof of this fix).
- Gate: `bun --bun run check`, `bun --bun run ci`.
- Browser smoke: see the #765 PR body for the live `/loops/new` walk-through and screenshot.
