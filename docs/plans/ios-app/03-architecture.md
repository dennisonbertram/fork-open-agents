# 03 — App Architecture

Status: planning document for the native iOS app (iPhone + iPad). This file defines the package
graph, project generation, state-management conventions, concurrency rules, persistence schema,
dependency injection, navigation, and code style. It restates — and never re-decides — the
canonical stack ratified in `docs/plans/ios-app/00-overview.md`:

- Xcode 26.x, Swift 6.2, Swift 6 language mode, strict concurrency complete
- SwiftUI-only, `@Observable` MVVM (TCA rejected)
- Minimum deployment iOS 26.0 / iPadOS 26.0 (Liquid Glass native)
- GRDB for local persistence (SwiftData rejected)
- XcodeGen (`project.yml`) for the app project; generated `.xcodeproj` is never committed
- swift-openapi-generator 1.12.2 + URLSession transport + `ClientMiddleware` auth
- Swift Testing for unit tests, swift-snapshot-testing 1.18.x, thin XCUITest smoke suite

Sibling documents: `00-overview.md` (decision record), `01-product-and-ux.md` (screens and v1
scope), `02-api-contract-and-networking.md` (OpenAPI pipeline + endpoint catalog),
`04-auth.md` (auth flows), `05-streaming-chat-engine.md` (chunk reducer + reconnect),
`06-testing-strategy.md`, `07-observability.md`, `08-ci-cd-release.md`,
`09-step-by-step-build-guide.md` (ordered build tasks).

Research grounding: `docs/plans/ios-app/research/20-swift-app-architecture.md`,
`research/07-data-model.md`, `research/11-web-client-consumption-patterns.md`,
`research/21-swift-openapi-generator.md`, `research/22-swift-sse-and-stream-protocol.md`,
`research/23-ios-auth-patterns.md`, `research/26-design-research.md`.

> Naming normalization: research brief 26 refers to the design-system package as
> `OpenAgentsDesignSystem`. The canonical package name in this plan is **`DesignSystem`**
> (path `ios/Packages/DesignSystem`). Wherever a research brief and this document disagree on a
> package name or path, this document wins.

```
    UITests/
      SmokeTests.swift            # thin XCUITest suite (see 06-testing-strategy.md)
  Packages/
    OpenAgentsCore/               # value vocabulary, zero dependencies
    OpenAgentsAPI/                # generated OpenAPI client (checked in)
    APIClient/                    # transport, middleware, typed facade
    AuthKit/                      # sign-in flows, Keychain token store

    PersistenceKit/               # GRDB database, caches, migrations
    Observability/                # os.Logger categories, request IDs, crash SDK init
    DesignSystem/                 # tokens, colors, shared components
    CodeUI/                       # syntax highlighting, code blocks, diff rendering
    OnboardingFeature/            # sign-in screens
    SessionsFeature/              # session list, create session
    ChatFeature/                  # transcript, composer, tool renderers
    ReposFeature/                 # repo browsing, repo dashboard
    BackgroundAgentsFeature/      # agents list, run timeline
    SettingsFeature/              # preferences, models, profiles, account
    AppShell/                     # composition root: tabs, routers, DI wiring
```

Rules:

- Every directory under `ios/Packages/` is an independent local Swift package with its own
  `Package.swift`. There is no umbrella package (the canonical stack chose multiple local
  packages under `ios/Packages/*`; research brief 20's single-umbrella sketch is superseded).
- The app target (`ios/App`) is a thin shell: `@main` struct, asset catalog, entitlements. All
  behavior lives in packages.
- `ios/App/OpenAgents.xcodeproj` is generated by XcodeGen and **gitignored**. The only
  checked-in project definition is `ios/App/project.yml`.
- Generated Swift in `ios/Packages/OpenAgentsAPI/Sources/OpenAgentsAPI/GeneratedSources/` **is
  checked in** (deliberate exception; CI drift check per `02-api-contract-and-networking.md`).
- If `01-product-and-ux.md` cuts a surface from v1 (e.g. background agents), delete the
  corresponding feature package; the infrastructure layer is unaffected.

`ios/.gitignore`:

```gitignore
App/OpenAgents.xcodeproj/
DerivedData/
*.xcuserstate
.DS_Store
```

The repo-root CI (`bun run ci`, Ultracite) must not lint `ios/**`; iOS has its own lane (see
`08-ci-cd-release.md` and `docs/plans/ios-app/research/10-process-rules.md`). Verify `bun run
check` ignores `ios/` when the directory is first created; add an ignore entry if it does not.

### 2.1 Layering

```
Layer 0 (vocabulary)      OpenAgentsCore
Layer 1 (infrastructure)  OpenAgentsAPI   APIClient   AuthKit   StreamEngine   PersistenceKit   Observability
Layer 2 (presentation     DesignSystem    CodeUI

App target                OpenAgents (depends on AppShell + Observability only)
```

Per-package dependency lists are normative in section 3 (each package's **Dependencies** line);
the layering above is the summary view.

### 2.2 Dependency rules (enforced by SPM, which hard-fails on cycles)

| Rule | Enforcement |
|---|---|
| A package may depend only on lower layers | review + SPM cycle failure |
| Feature packages never import other feature packages | review; cross-feature navigation uses routes + closures injected by `AppShell` (section 10.5) |
| Only `APIClient` imports `OpenAgentsAPI` | generated `Components.Schemas.*` types never leak above the `APIClient` boundary |
| Only `PersistenceKit` imports `GRDB` | record types and SQL stay inside the package |
| Only `CodeUI` imports the syntax-highlighting dependency | keeps the heavy dependency quarantined |
| `OpenAgentsCore` has zero dependencies (Foundation only) | manifest review |
| Shared cross-feature types sink into `OpenAgentsCore` | review |

## 3. Package-by-package specification

Every package follows the same internal shape: `Sources/<PackageName>/` with PascalCase area
folders, `Tests/<PackageName>Tests/` using Swift Testing. Public API is explicit (`public`
keyword); everything else is `internal`.

### 3.1 `OpenAgentsCore` — the value vocabulary

- **Path:** `ios/Packages/OpenAgentsCore`
- **Responsibility:** pure value types and tiny Foundation-only utilities shared by every other
  package. No I/O, no SwiftUI, no UIKit.
- **Dependencies:** none.
- **Platforms:** `.iOS(.v26), .macOS(.v15)` (macOS enables fast host-run `swift test`).

Contents (folders under `Sources/OpenAgentsCore/`):

| Folder | Contents |
|---|---|
| `Models/` | Domain structs mirroring the server's client-facing types from `research/07-data-model.md`: `Session` (list shape = `SessionWithUnread`), `SessionDetail` (full row incl. `sandboxState`, `cachedDiff`), `Chat` (= `ChatSummary`), `AgentUIMessage` + `AgentMessagePart` + `WebAgentMetadata` + data-part payload structs (`CommitData`, `PrData`, `SnippetData`, `WorkspaceStatusData`, `VerifiedBuildData`, `RuntimeProofData`), `Repo` (= `InstallationRepository`, snake_case wire keys mapped here), `GitHubInstallation`, `InferenceProfile` (= `SafeInferenceProfile`), `UserPreferences` (= `UserPreferencesData`, 15 fields), `UserInfo` (= `SessionUserInfo`), `DiffFile`/`DiffResponse`, `BackgroundAgent`/`BackgroundAgentRun`/`BackgroundAgentEvent`, `UsageSummary` types. Exact field lists are pinned by `02-api-contract-and-networking.md`; chat message part details by `05-streaming-chat-engine.md`. |
| `JSON/` | `JSONValue` (recursive any-JSON enum, `Codable`, `Sendable` — the only sanctioned replacement for `Any`). |
| `Enums/` | Server-evolvable enums use the lenient pattern: `RawRepresentable` structs or enums with an `.unknown(String)` case. Decoding an unknown value must never throw (mirrors web behavior; see `research/07-data-model.md` global conventions). |
| `DeepLink/` | `DeepLink` enum + `DeepLink.init?(url: URL)` parser for `openagents://` URLs (section 10.6). Uses raw `String` ids only, so it has no feature dependencies. |
| `Auth/` | `protocol AuthTokenStore: Sendable` (`currentToken() async -> String?`, `update(token:) async`, `clear() async`). Defined here so `APIClient` and `AuthKit` can share it without depending on each other. |
| `Utilities/` | `AdaptivePoller` (interval helper encoding the web cadences from `research/11-web-client-consumption-patterns.md` §4: fast-while-active / slow-while-idle / paused-while-backgrounded), ISO-8601 date coding helpers (fractional seconds), `A11yID` (accessibility-identifier constants shared with UITests, e.g. `A11yID.Chat.composerField = "chat.composer.field"`). |
| `Errors/` | `AppError` — the app-level error vocabulary: `.unauthenticated`, `.offline`, `.server(status: Int, message: String)`, `.decoding(String)`, `.cancelled`. |

Wire-name rule: model property names match the JSON wire names exactly (`sessionId`, `chatId`,
`prNumber`, `repoOwner`) so `Codable` needs no `CodingKeys`. This deliberately deviates from the
Swift API Design Guidelines `ID` capitalization; the `Id` spelling is used consistently
everywhere, including non-wire code (section 11.2).

### 3.2 `OpenAgentsAPI` — generated OpenAPI client

- **Path:** `ios/Packages/OpenAgentsAPI`
- **Responsibility:** the checked-in, generated Swift client for `apps/web/openapi.json`.
  Nothing hand-written lives here except the package manifest, the generator config, and the
  copied spec.
- **Dependencies:** `OpenAPIRuntime` (1.12.0), `OpenAPIURLSession` (1.3.0); plugin dependency
  `swift-openapi-generator` (1.12.2).
- **Layout:**

```
ios/Packages/OpenAgentsAPI/
  Package.swift
  Package.resolved                          # committed (package-level resolution)
  Sources/OpenAgentsAPI/
    openapi.json                            # copied from apps/web/openapi.json by generate-api.sh
    openapi-generator-config.yaml
    GeneratedSources/
      Types.swift                           # generated, committed
      Client.swift                          # generated, committed
```

`openapi-generator-config.yaml`:

```yaml
generate:
  - types
  - client
accessModifier: public
namingStrategy: idiomatic
additionalFileComments:
  - "swift-format-ignore-file"
```

Regeneration command (wrapped by `ios/Scripts/generate-api.sh`; the full pipeline — spec
expansion, `additionalProperties:false` stripping, drift check — is owned by
`02-api-contract-and-networking.md`):

```bash
swift package --package-path ios/Packages/OpenAgentsAPI \
  --allow-writing-to-package-directory generate-code-from-openapi \
  --target OpenAgentsAPI
```

No other package may import `OpenAgentsAPI` except `APIClient`.

### 3.3 `APIClient` — transport, middleware, typed facade

- **Path:** `ios/Packages/APIClient`
- **Responsibility:** owns the two `URLSession`s (REST + streaming), the OpenAPI `Client`
  construction, auth/request-id/logging middleware, error mapping, and a typed facade that
  converts generated types into `OpenAgentsCore` domain models.
- **Dependencies:** `OpenAgentsAPI`, `OpenAgentsCore`, `Observability`.

Public API sketch:

```swift
public struct APIClientConfiguration: Sendable {
  public var baseURL: URL
  public init(baseURL: URL)
}

/// Errors every caller switches over. Mapped once from ClientError / undocumented statuses.
public typealias APIError = OpenAgentsCore.AppError

public final class OpenAgentsClient: Sendable {
  public init(
    configuration: APIClientConfiguration,
    tokenStore: any AuthTokenStore,
    onUnauthenticated: @escaping @Sendable () async -> Void
  )
  // Domain facades. Each method calls the generated client, maps types, throws APIError.
  public var sessions: SessionsAPI { get }     // list, detail, create, patch, archive, diff
  public var chats: ChatsAPI { get }           // list, snapshot, create, fork, patch, read-receipt, messages
  public var repos: ReposAPI { get }           // installations, installation repos
  public var settings: SettingsAPI { get }     // preferences, models, inference profiles, skills, agents
  public var backgroundAgents: BackgroundAgentsAPI { get }
  public var usage: UsageAPI { get }
}

/// Seam consumed by StreamEngine: builds authorized URLRequests against the same base URL
/// and streaming URLSession, without exposing the generated client.
public protocol AuthorizedRequestBuilding: Sendable {
  func request(path: String, method: String, jsonBody: Data?) async throws -> URLRequest
  var streamingSession: URLSession { get }
}
extension OpenAgentsClient: AuthorizedRequestBuilding {}
```

Internal pieces (names fixed so other docs can reference them):

- `AuthenticationMiddleware: ClientMiddleware` — stamps `Authorization: Bearer <token>` from the
  injected `AuthTokenStore`; inspects every response for the `set-auth-token` header and calls
  `tokenStore.update(token:)` (rotation contract from `research/23-ios-auth-patterns.md` §1).
- `RequestIDMiddleware: ClientMiddleware` — attaches a client-generated request id header and
  logs `x-request-id` from responses (details in `07-observability.md`).
- `ErrorMapper` — maps generated `undocumented` cases and `{ "error": string }` bodies to
  `APIError`; on `.unauthenticated` (HTTP 401 with message `"Not authenticated"`), invokes
  `onUnauthenticated` exactly once per failure (mirrors the web's global SWR 401 handler,
  `research/11-web-client-consumption-patterns.md` §1).
- Two `URLSessionConfiguration`s: `rest` (default timeouts, `waitsForConnectivity = true`) and
  `streaming` (`timeoutIntervalForRequest = 600`, `timeoutIntervalForResource` left at default;
  rationale in `research/22-swift-sse-and-stream-protocol.md` §6).
- The OpenAPI `Client` is constructed with
  `Configuration(dateTranscoder: .iso8601WithFractionalSeconds)`.

### 3.4 `AuthKit` — sign-in flows and token custody

- **Path:** `ios/Packages/AuthKit`
- **Responsibility:** the better-auth native dance: `ASWebAuthenticationSession` Vercel OAuth
  with `openagents://auth-callback` handoff, native Sign in with Apple, Keychain token storage,
  sign-out, account deletion entry point. Protocol contracts come from `04-auth.md`.
- **Dependencies:** `OpenAgentsCore`, `Observability`. (Deliberately **not** `APIClient`: the
  better-auth endpoints are not part of the OpenAPI spec; AuthKit issues its own small
  URLSession calls. The shared seam is `AuthTokenStore` in `OpenAgentsCore`.)
- **Platforms:** iOS only (imports `AuthenticationServices`, `UIKit`).

Public API sketch:

```swift
public enum AuthState: Equatable, Sendable {
  case unknown          // app launch, keychain not yet read
  case signedOut
  case signingIn
  case signedIn(UserInfo)
}

@MainActor @Observable
public final class AuthController {
  public private(set) var state: AuthState
  public init(tokenStore: KeychainTokenStore, baseURL: URL)
  public func bootstrap() async                       // read keychain, validate via GET /api/auth/info
  public func signInWithVercel() async throws         // ASWebAuthenticationSession flow (04-auth.md)
  public func signInWithApple() async throws          // ASAuthorizationAppleIDProvider → idToken POST
  public func handleAuthCallback(_ url: URL) -> Bool  // true if the URL was an auth deep link
  public func signOut() async                         // server sign-out + Keychain wipe + cache nuke hook
  public func deleteAccount() async throws            // guideline 5.1.1(v); endpoint per 04-auth.md
  public var onSignedOut: (@Sendable () async -> Void)?  // AppShell wires DB nuke here
}

public actor KeychainTokenStore: AuthTokenStore {
  public init(service: String = "com.openagents.app.session")
  // kSecClassGenericPassword, kSecAttrAccessibleAfterFirstUnlockThisDeviceOnly
}
```

### 3.5 `StreamEngine` — SSE consumption and chat runtimes

- **Path:** `ios/Packages/StreamEngine`
- **Responsibility:** everything between raw SSE bytes and a renderable message list: the
  line-level SSE parser, `UIMessageChunk` decoding, the reducer actor, 75 ms coalescing, the
  resume/reconnect policy, and per-chat runtime lifecycle. The full behavioral specification
  (chunk catalog, reducer rules, replay-from-chunk-0 handling, backoff schedule) is
  `05-streaming-chat-engine.md`; this section fixes only the package shape and names.
- **Dependencies:** `APIClient` (for `AuthorizedRequestBuilding`), `OpenAgentsCore`,
  `Observability`.

Public API sketch:

```swift
/// Wire chunk union. Decodable with an `.unknown(type:)` fallback — never throws on new types.
public enum UIMessageChunk: Sendable, Decodable { /* full catalog in 05-streaming-chat-engine.md */ }

public enum ChatStreamStatus: Equatable, Sendable {
  case ready, submitted, streaming, error(String)
}

/// One per chat. The iOS equivalent of the web's useChat + chat-instance-manager pair.
@MainActor @Observable
public final class ChatRuntime: Identifiable {
  public let chatId: String
  public let sessionId: String
  public private(set) var messages: [AgentUIMessage]
  public private(set) var status: ChatStreamStatus
  /// True when the server says a stream is live even though no local connection exists
  /// (effectiveStatus reconciliation, research/11 §10).
  public private(set) var serverSaysStreaming: Bool

  public func send(parts: [OutgoingMessagePart]) async
  public func stop() async                                  // POST /api/chat/{chatId}/stop, then abort
  public func resumeIfNeeded() async                        // GET /api/chat/{chatId}/stream; 204 → refetch
  public func setMessages(_ messages: [AgentUIMessage])     // history hydration from cache/REST
  public func addToolApprovalResponse(approvalId: String, approved: Bool, reason: String?) async
  public func addToolOutput(toolCallId: String, toolName: String, output: JSONValue) async
}

/// App-scoped registry; keeps runtimes alive across navigation while a turn streams.
@MainActor
public final class ChatRuntimeRegistry {
  public init(requests: any AuthorizedRequestBuilding)
  public func runtime(forChatId chatId: String, sessionId: String) -> ChatRuntime
  public func releaseIdleRuntimes()   // evict non-streaming runtimes; called on memory warning + scene background
}

/// Off-main reducer actor; consumes parsed chunks and publishes coalesced snapshots.
public actor ChatStreamReducer { /* specified in 05-streaming-chat-engine.md */ }
```

```swift
let swiftSettings: [SwiftSetting] = [
```

## 5. How the layers interact (one worked flow)

Opening a chat and sending a message:

1. `AppRouter.sessionsPath` gains `.chat(sessionId:chatId:)`; AppShell's
   `navigationDestination(for: SessionsRoute.self)` constructs `ChatScreen` with a new
   `ChatStore`.
2. `ChatStore.activate()`: fetch the shared `ChatRuntime` from `ChatRuntimeRegistry` (it may
   already be streaming from a previous visit), start the GRDB transcript observation for
   instant cached hydration, refresh via `api.chats.snapshot(...)`; if the runtime is idle but
   the snapshot reports `isStreaming`, call `runtime.resumeIfNeeded()`.
3. Send → `ChatRuntime.send(parts:)` → StreamEngine POSTs `/api/chat` via
   `AuthorizedRequestBuilding`, parses SSE off-main, reduces in `ChatStreamReducer`, publishes
   coalesced snapshots to `ChatRuntime.messages` on the main actor.
4. On `finish`, `ChatStore` refetches persisted messages and writes them through
   `TranscriptCache.replaceMessages(chatId:_:)`. Navigating away never stops generation —
   `ChatRuntimeRegistry` keeps the runtime alive (web chat-instance-manager parity).

## 7. `@Observable` MVVM conventions

### 7.1 The three roles

| Role | What it is | Rules |
|---|---|---|
| **Model** | Value types (`struct`/`enum`) in `OpenAgentsCore` (domain) or feature-local view-state structs | Immutable from the view's perspective; `Equatable + Sendable`; no methods with side effects; no references to stores or clients |
| **Store** | `@MainActor @Observable final class`, one per screen (or per long-lived concern) | Owns the screen's state as `private(set)` vars; exposes intent methods (`refresh()`, `send(_:)`, `archive(sessionId:)`); receives dependencies via `init`; never imports SwiftUI (assert: stores must compile without `import SwiftUI`) |
| **View** | SwiftUI `struct` | Renders store state and calls intent methods; `@State` only for view-local UI state (focus, sheet visibility, scroll position); never calls `APIClient`/`PersistenceKit` directly; never constructs other features' stores |

Naming: `<Thing>Store` for observable state owners, `<Thing>Client` / `<Thing>API` for service
protocols, `<Thing>Screen` for navigable view roots, `<Thing>View` for components, `<Thing>Row`
for list rows. No `ViewModel` suffix anywhere.

### 7.2 Ownership and lifetime

1. **Screen-scoped stores** are constructed at navigation time (inside the
   `navigationDestination` closure in AppShell, which can read `AppEnvironment` from the
   SwiftUI environment) and owned by the screen via `@State`:

   ```swift
   public struct SessionListScreen: View {
     @State private var store: SessionListStore
     public init(store: SessionListStore) { _store = State(initialValue: store) }
     public var body: some View {
       List(store.sessions) { session in SessionRow(session: session) }
         .task { await store.activate() }        // cancelled automatically on disappear
         .refreshable { await store.refresh() }
     }
   }
   ```

   Long-running work inside a store must be tied to `Task`s the store owns and cancels in
   `deactivate()`; the `.task` modifier's auto-cancellation is the default disposal path.
2. **App-scoped stores** live for the process and are owned by `AppEnvironment`:
   `AuthController`, `AppRouter`, `SessionListStore` (the sessions poll also powers tab badges
   and "agent finished" notices, so it is app-scoped — mirroring the web's sessions poll),
   `ChatRuntimeRegistry`.
3. **`ChatRuntime` is chat-scoped but outlives its screen** while a turn is streaming
   (registry rules in section 3.5). Eviction: non-streaming runtimes are released on memory
   warnings and when the scene backgrounds.
4. Stores never retain views. Views never retain clients. Models never reference stores.
5. **Streaming-state isolation (mandatory):** completed messages are value types in an array;
   the in-flight assistant message updates are confined to the `ChatRuntime` and flushed on the
   75 ms coalescing tick, so token updates never invalidate the transcript list
   (`research/20-swift-app-architecture.md` §3.3, `research/22` §8). Transcript rows are narrow
   subviews (`MessageRow`) keyed by stable part identity (`toolCallId`, text-block id).

### 7.3 Preview strategy

- Every public `*Screen`, every DesignSystem component, and every tool renderer has a
  `#Preview`.
- Previews never hit the network: they use `AppEnvironment.preview()` (mock clients +
  `AppDatabase.inMemory()`); a mock client that receives an unstubbed call crashes the preview
  with a clear message.
- Fixture data lives in one `PreviewFixtures.swift` per feature target (e.g.
  `PreviewFixtures.session`, `PreviewFixtures.streamingMessage`); snapshot tests reuse the same
  fixtures so previews and snapshots cannot drift.
- Known SPM-target preview flakiness (`research/20` §4.3): if previews stall, add a minimal
  preview-host app later; do not move code out of packages to work around it.

## 8. Dependency injection

Environment-based, one container, constructor injection below it. No DI framework.

### 8.1 The container

```swift
// ios/Packages/AppShell/Sources/AppShell/AppEnvironment.swift
@MainActor @Observable
public final class AppEnvironment {
  public let api: OpenAgentsClient
  public let auth: AuthController
  public let db: AppDatabase
  public let chatRuntimes: ChatRuntimeRegistry
  public let router: AppRouter
  public let sessionList: SessionListStore        // app-scoped (badges + completion notices)

  public static func live() -> AppEnvironment {
    let baseURL = AppConfig.baseURL()             // Info.plist OpenAgentsBaseURL + DEBUG override
    let tokenStore = KeychainTokenStore()
    let auth = AuthController(tokenStore: tokenStore, baseURL: baseURL)
    let api = OpenAgentsClient(
      configuration: .init(baseURL: baseURL),
      tokenStore: tokenStore,
      onUnauthenticated: { await auth.signOut() }
    )
    let db = try! AppDatabase.open(at: AppDatabase.defaultURL())   // unrecoverable ⇒ crash early
    auth.onSignedOut = { try? await db.nuke() }
    // … construct registry, router, stores; return
  }

  public static func preview() -> AppEnvironment { /* mocks + in-memory DB */ }

  public func handle(url: URL) {
    if auth.handleAuthCallback(url) { return }
    if let link = DeepLink(url: url) { router.open(link) }
  }
}
```

### 8.2 Injection rules

1. `RootView` puts the container into the SwiftUI environment once:
   `.environment(environment)`. Reading it requires
   `@Environment(AppEnvironment.self) private var env`.
2. Only **composition sites** read `AppEnvironment` from the environment: AppShell's tab roots
   and `navigationDestination` closures. Feature views and components never read it.
3. Stores receive the **narrowest dependency** they need via `init`
   (`SessionListStore(api: env.api.sessions, cache: env.db.sessions)`), not the whole container.
   Test doubles implement the same facade protocol; no global mutable state, no singletons
   except `SyntaxHighlighter.shared` (stateless cache).
4. Mocks live in the package that defines the protocol, in a `Mocks/` folder, `public`, and are
   used by both previews and tests. (Accepted trade-off: mocks compile into release builds;
   they contain no secrets and negligible size.)

## 9. GRDB persistence

### 9.1 Principles

- The server is the source of truth. The cache exists for instant cold-start rendering and
  offline reading. It is **disposable**: the escape hatch for any migration problem is
  `nuke()` + re-sync.
- Storage pattern per entity: **raw JSON blob column + a few indexed columns** for list
  rendering/sorting. Domain models decode from the JSON blob, so server field additions never
  require a schema migration.
- One database per device, scoped to one account: `appMeta.accountUserId` is checked on every
  `bootstrap()`; if `/api/auth/info` returns a different user id, the database is nuked before
  any write.
- Network-only (deliberately **not** cached) in v1: observability events, workflow runs, usage
  aggregates, harness/verified-build data, background-agent run lists, git status, sandbox
  status, files/skills lists. They are cheap to refetch and stale copies are misleading.

### 9.2 Database setup

- Location: `Application Support/OpenAgents/openagents.sqlite` (`DatabasePool`, WAL mode).
- File protection: `.completeUntilFirstUserAuthentication`.
- `Configuration.foreignKeysEnabled = true` (default in GRDB 7).
- Migrations via `DatabaseMigrator`; in DEBUG, `migrator.eraseDatabaseOnSchemaChange = true`.

### 9.3 Schema (migration `v1`)

Table names are camelCase singular (GRDB convention). All timestamps are `Date` columns
(`.datetime`); server ISO-8601 strings are parsed at the APIClient boundary; all values UTC.

| Table | Mirrors (server) | Columns |

### 9.4 Record types and read/write patterns

- One `struct <Name>Record: Codable, FetchableRecord, PersistableRecord` per table, internal to
  PersistenceKit. Caches map records ↔ `OpenAgentsCore` models at their boundary.
- **Writes** are transactional and idempotent. List endpoints replace whole collections:

  ```swift
  public func replaceAll(_ sessions: [Session]) async throws {
    try await writer.write { db in
      let ids = sessions.map(\.id)
      try SessionRecord.filter(!ids.contains(Column("id"))).deleteAll(db)   // cascades chats/messages
      for session in sessions { try SessionRecord(session).upsert(db) }     // preserves detailJson
      try SyncStateRecord(collection: "sessions", lastRefreshedAt: .now).upsert(db)
    }
  }
  ```

  `upsert` must not clobber `detailJson`/`detailFetchedAt` (use a targeted
  `updateChanges`/column-list upsert). Transcript writes replace per chat:
  `replaceMessages(chatId:_:)` deletes the chat's rows and inserts with fresh `position`s in
  one transaction (the server has no message paging — snapshots are whole arrays,
  `research/11` §8).
- **Reads** are reactive: every cache exposes `ValueObservation … .values(in: reader)` as an
  `AsyncSequence`, with `.removeDuplicates()`. Stores consume it:

  ```swift
  @MainActor @Observable
  public final class SessionListStore {
    public private(set) var sessions: [Session] = []
    public private(set) var freshness: Freshness = .unknown   // .fresh, .stale(since: Date), .offline(since: Date?)

    public func activate() async {
      observationTask = Task {
        for try await rows in cache.observeAll() { self.sessions = rows }   // main-actor hop is implicit
      }
      await refresh()
      pollTask = Task { await poller.run { await self.refresh() } }         // AdaptivePoller cadence
    }

    public func refresh() async {
      do {
        let fetched = try await api.list()
        try await cache.replaceAll(fetched)
        freshness = .fresh
      } catch let error as AppError where error == .offline {
        freshness = .offline(since: await cache.lastRefreshedAt())
      } catch { /* log; keep cached data; surface error state */ }
    }
  }
  ```

### 9.5 Refresh-from-network and offline behavior

- **Stale-while-revalidate everywhere:** screens render cached rows immediately (observation
  fires on appear), then `refresh()` runs; the UI updates only via the observation. There is no
  spinner when cache exists — only when the table is empty.
- **The store is the sync point.** There is no separate sync daemon: `refresh()` =
  API fetch → cache write. Polling cadences copy the web client
  (`research/11` §4): sessions 3 s while any `hasStreaming` else 30 s; chats 1 s while
  streaming, 8 s idle-foreground; all polls pause when `scenePhase != .active`.
- **Offline reads:** all cached collections render with a staleness indicator driven by
  `syncState.lastRefreshedAt`. Transcripts are readable offline.
- **Offline writes:** none in v1. Mutations require network; the composer disables send and
  shows an offline notice (final UX in `01-product-and-ux.md`). There is no outbound queue.
- **Drafts:** composer text autosaves to `chatDraft` (debounced 1 s), restored on screen entry,
  deleted on successful send.
- **Pruning:** on launch, `pruneTranscripts(keepingRecentChats: 50)` deletes `chatMessage` rows
  for chats outside the 50 most recently active; `repo` rows older than 7 days are deleted.
- **Nuke triggers:** sign-out, account-id mismatch, GRDB migration failure in release builds
  (log, nuke, re-open, re-sync).

## 10. Navigation architecture

### 10.1 Root structure

- Signed-out: `SignInScreen` (no tabs).
- Signed-in: `TabView` with four tabs — final tab set is owned by `01-product-and-ux.md`; the
  mechanics below are unchanged if it differs:

```swift
public enum AppTab: String, CaseIterable, Sendable { case sessions, repos, agents, settings }
```

- iPhone: each tab hosts a `NavigationStack` bound to a typed route array.
- iPad (regular width): the Sessions tab uses `NavigationSplitView` (sidebar = session list,
  detail = chat/workspace) driven by the **same** `SessionsRoute` values; `TabView` adapts to
  the iPadOS 26 sidebar representation automatically. Other tabs keep stacks.

### 10.2 Router

```swift
// ios/Packages/AppShell/Sources/AppShell/AppRouter.swift
@MainActor @Observable
public final class AppRouter {
  public var selectedTab: AppTab = .sessions
  public var sessionsPath: [SessionsRoute] = []
  public var reposPath: [ReposRoute] = []
  public var agentsPath: [AgentsRoute] = []
  public var settingsPath: [SettingsRoute] = []

  public func open(_ link: DeepLink) {
    switch link {
    case .session(let id):
      selectedTab = .sessions
      sessionsPath = [.session(id: id)]
    case .chat(let sessionId, let chatId):
      selectedTab = .sessions
      sessionsPath = [.session(id: sessionId), .chat(sessionId: sessionId, chatId: chatId)]
    case .backgroundRun(let runId):
      selectedTab = .agents
      agentsPath = [.runDetail(runId: runId)]
    }
  }
}
```

### 10.3 Route enums

Routes are plain `Hashable` data exported by the feature that semantically owns them
(importable by AppShell without coupling features to each other):

```swift
// SessionsFeature
public enum SessionsRoute: Hashable, Sendable {
  case session(id: String)
  case chat(sessionId: String, chatId: String)
  case diff(sessionId: String)
  case createSession
}
```

`ReposRoute`, `AgentsRoute`, `SettingsRoute` follow the same pattern.

### 10.4 `NavigationPath` policy

Type-erased `NavigationPath` is **prohibited**. Each stack binds a homogeneous typed array
(`NavigationStack(path: $router.sessionsPath)`) because typed arrays are constructible from
deep links, assertable in unit tests, and exhaustively matched in `navigationDestination`.
(`NavigationPath` would only be needed for heterogeneous pushes, which the route-enum design
eliminates by construction.)

### 10.5 Destination registration and cross-feature navigation

AppShell owns every `NavigationStack`/`NavigationSplitView` and all
`navigationDestination(for:)` registrations; feature packages export screens and route enums
only:

```swift
NavigationStack(path: $router.sessionsPath) {
  SessionListScreen(store: env.sessionList, onCreate: { router.sessionsPath.append(.createSession) })
    .navigationDestination(for: SessionsRoute.self) { route in
      switch route {
      case .session(let id):
        SessionScreen(store: SessionStore(sessionId: id, api: env.api.sessions, db: env.db))
      case .chat(let sessionId, let chatId):
        ChatScreen(store: ChatStore(
          chatId: chatId, sessionId: sessionId,
          runtimes: env.chatRuntimes, api: env.api.chats, db: env.db))
      case .diff(let sessionId):
        SessionDiffScreen(store: SessionDiffStore(sessionId: sessionId, api: env.api.sessions))
      case .createSession:
        CreateSessionScreen(store: CreateSessionStore(api: env.api, db: env.db))
      }
    }
}
```

Cross-feature intents (e.g. ReposFeature's "open a session for this repo") are closures injected
by AppShell (`onOpenSession: (String) -> Void` appending to `router.sessionsPath`). Features
never mutate the router directly and never import each other.

### 10.6 Deep links

Handled in `AppEnvironment.handle(url:)` (section 8.1): AuthKit gets first refusal, then
`DeepLink(url:)`.

| URL | Behavior |
|---|---|
| `openagents://auth-callback?...` | Consumed by `AuthController.handleAuthCallback` (normally intercepted inside `ASWebAuthenticationSession`; `onOpenURL` is the fallback path). Never routed. |
| `openagents://sessions/{sessionId}` | tab `.sessions`, path `[.session(id:)]` |
| `openagents://sessions/{sessionId}/chats/{chatId}` | tab `.sessions`, path `[.session, .chat]` |
| `openagents://background-runs/{runId}` | tab `.agents`, path `[.runDetail(runId:)]` (reserved for future push notifications) |
| anything else | ignored, logged via `Log.ui` |

`DeepLink` parsing lives in `OpenAgentsCore` with exhaustive unit tests (valid, trailing slash,
unknown host, missing ids).

### 10.7 Scene-phase reconciliation

AppShell observes `scenePhase`. On `.active` after background (mirrors the web's tab-resume
behavior, `research/11` §2): resume any in-flight `ChatRuntime` (`resumeIfNeeded()`), trigger
`refresh()` on the visible store, resume pollers. On `.background`: pause pollers, let streams
die (the server workflow is durable), persist drafts.

### 11.2 Code rules

- One primary responsibility per file; extract child views/hooks-equivalents instead of growing
  a screen file (mirror of the repo's separation-of-concerns rule). Soft limit: a `View` body
  over ~100 lines or a file over ~300 lines must be split.
- Never `Any` — use `JSONValue` and narrow with pattern matching (mirror of "never use `any`").
- No force unwraps, `try!`, or `as!` outside tests, previews, and the single documented
  `AppDatabase.open` crash-early site. Each surviving instance carries a `// SAFETY:` comment.
- No `print`; use `Observability.Log` categories. Never log token values or message content at
  `.default` level (privacy rules in `07-observability.md`).
- Explicit `public` API per package; no `open`; `internal` default.
- Decode leniently: server enums via unknown-case fallback; unknown SSE chunk types via
  `.unknown` (mirror of Zod-validation discipline, adapted to the consumer side).
- `@unchecked Sendable` requires a `// SAFETY:` comment and reviewer sign-off; expected count
  in v1: zero.
- Doc comments (`///`) on every public declaration in Layer 0–2 packages.
- US English; double-quoted strings (Swift default); trailing commas in multiline literals.

## 12. Swift 6.2 strict-concurrency rules

### 12.1 Per-package isolation posture

| Package | Default isolation | Why |
|---|---|---|
| OpenAgentsCore | `nonisolated` | Pure `Sendable` values; MainActor default would isolate conformances pointlessly |
| OpenAgentsAPI | `nonisolated` | Generated client is actor-agnostic |
| APIClient | `nonisolated` | I/O layer; callable from any actor |
| StreamEngine | `nonisolated` (explicit `@MainActor` on `ChatRuntime`, `ChatRuntimeRegistry`) | Reducer and parser run off-main by design |
| PersistenceKit | `nonisolated` | GRDB schedules its own queues; wrapping in MainActor would serialize I/O onto the UI thread |
| Observability | `nonisolated` | Loggers are Sendable |
| AuthKit | `MainActor` | Drives system UI (`ASWebAuthenticationSession`); `KeychainTokenStore` is its own actor |
| DesignSystem, CodeUI | `MainActor` (CodeUI's `SyntaxHighlighter` is its own actor) | SwiftUI views |
| All features, AppShell, app target | `MainActor` | UI |

### 12.2 Actor inventory (complete; adding a new actor requires a design note)

| Actor | Package | Protects |
|---|---|---|
| `ChatStreamReducer` | StreamEngine | in-flight turn state; consumes chunks off-main |
| `KeychainTokenStore` | AuthKit | Keychain read/modify/write + token rotation atomicity |
| `SyntaxHighlighter` | CodeUI | highlight cache; CPU-heavy work off-main |

Everything else stateful is either `@MainActor @Observable` (stores, runtimes, controllers) or
delegated to GRDB's internal scheduling.

### 12.3 Rules

1. **`@MainActor` policy:** all views, stores, routers, and `AppEnvironment` are MainActor.
   Stores are MainActor even when they await background work — suspension points handle the
   hops; no `DispatchQueue` anywhere in the codebase.
2. **`nonisolated` is allowed** only for pure functions (no mutable state) — formatting,
   mapping, parsing helpers inside MainActor-default packages. If a helper grows beyond a few
   lines or becomes hot, move it to a Layer 0/1 package instead.
3. **`@concurrent` is allowed** only in nonisolated-default packages, only on CPU-bound leaf
   functions, each justified by a comment naming the workload. Sanctioned sites: SSE chunk
   decoding (StreamEngine), syntax highlighting (CodeUI), diff/markdown pre-parsing
   (CodeUI/ChatFeature support code that lives in StreamEngine or CodeUI).
4. **Sendable conventions:** all `OpenAgentsCore` models declare `Sendable` explicitly; any
   protocol whose witnesses cross actors is declared `: Sendable`; closures stored across
   concurrency boundaries are `@Sendable`. Compiler errors are fixed by restructuring
   (value snapshots, actors), never by `@preconcurrency`/`@unchecked` (exception process in
   11.2).
5. **Cancellation:** every long-lived `Task` is owned by a store/runtime and cancelled in
   `deactivate()`/`deinit`; streaming tasks must check `Task.isCancelled` between chunks so
   leaving a screen tears down the URLSession request (web parity: navigation does not stop
   server generation, only the local connection — and `ChatRuntimeRegistry` deliberately keeps
   the local runtime alive while streaming).
6. `@preconcurrency import` is permitted only for third-party SDKs that predate Swift 6
   (expected: possibly Highlightr), recorded in the dependency pin table when used.
