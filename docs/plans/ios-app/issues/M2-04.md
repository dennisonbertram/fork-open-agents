## Why this matters

Every deterministic test layer in the iOS plan — Swift Testing units, SSE fixture replay, generated-client contract tests, GRDB cache tests, snapshot tests — needs the same shared infrastructure: an injectable in-process network stub that can deliver SSE chunk-by-chunk, an in-process HTTP server tier, fixture loading, temp databases, fixed clocks/locales, and a tag taxonomy. If each feature slice invents its own, the suite becomes flaky and inconsistent before the first real feature test exists. This issue also resolves the single riskiest open technical question in the testing plan (research brief 24, flagged medium-confidence): whether `URLSession.bytes(for:)` preserves `URLProtocol` chunk boundaries on the iOS 26 SDK. The mandatory spike test answers it now, while the fallback (FlyingFox tier) is cheap to adopt. Finally, the `UnitTests`/`UISmoke` test plans give CI and humans one named, stable entry point each for "run the deterministic suite" and "run the UI smoke" — the iOS analog of `bun run ci`'s test step.

## User/operator path protected

Protected path (per the M2 milestone goal): **every deterministic test layer has shared infrastructure before the first feature test is written.** Concretely: a contributor (human or agent) on a machine with Xcode 26.x runs `swift test --package-path ios/Packages/OpenAgentsTestSupport` and gets a green, parallel-safe helper suite; then runs `xcodegen generate --spec ios/App/project.yml --project ios/App` followed by `xcodebuild test … -testPlan UnitTests -only-test-configuration CI` and every package test target plus the snapshot canary executes — with UI tests excluded and snapshot recording forced to `never`. This is the substrate for catalog paths P3/P4/P5/P9 in `docs/plans/ios-app/06-testing-strategy.md` §2 (stream replay, resume, part rendering, offline cache), which cannot be built test-first without it.

## Behavior contract

- Given a `URLSession` built from `StubURLProtocol.makeEphemeralSession()` and a registered SSE stub with two events and a 200 ms inter-chunk delay, When the test consumes `session.bytes(for:)`, Then the response is an `HTTPURLResponse` carrying `Content-Type: text/event-stream` and `x-vercel-ai-ui-message-stream: v1`, exactly two `\n\n`-terminated emissions are assembled, and the arrival gap between emission 1 and emission 2 is ≥ 100 ms (proving chunk boundaries were not coalesced). (Happy path — the mandatory spike from 06 §5.2.)
- Given the spike test fails on the pinned iOS 26.0 simulator (URLSession coalesces the chunks), When the implementer observes the failure, Then the outcome is recorded in `docs/agents/lessons-learned.md` in the same PR, the spike test is rewritten against `TestHTTPServer` (FlyingFox over real HTTP, same two-emission assertion), and SSE-parser testing in later milestones is documented as FlyingFox-tier in this issue's PR description. (Designed failure path.)
- Given `FixtureLoader(bundle: .module)` and a request for a missing resource, When `data("sse/does-not-exist.sse.txt")` is called, Then it throws `FixtureLoaderError.resourceNotFound` whose description contains the relative path, and the Swift Testing failure message is self-diagnosing. (Error case.)
- Given the committed self-test fixture `minimal-two-events.sse.txt` (three leading `:` metadata comment lines per 06 §5.5, then two events), When `sseEventChunks(_:)` splits it, Then exactly two chunks are returned, each suffixed `\n\n`, and the second equals `data: [DONE]\n\n`. (Edge case: comment lines belong to the first event block.)
- Given two `TestHTTPServer` instances started concurrently on port 0, When both `start()` calls return, Then the assigned ports are distinct and non-zero, and a `URLSession` GET against a registered JSON route returns the registered status/body while `receivedRequests` records the method, path, and headers (including any `x-request-id`). (Parallel-safety edge case.)
- Given `TemporaryDatabaseDirectory.make()` called twice, When both values are inspected, Then the directory URLs are distinct, exist on disk, and `cleanUp()` removes them; `databaseURL` ends in `test.sqlite`. The helper does **not** import GRDB (03 §2.2: only `PersistenceKit` imports GRDB) — `PersistenceKit` tests pass `databaseURL` to `AppDatabase.open(at:)` themselves.
- Given the regenerated Xcode project, When `xcodebuild test … -testPlan UnitTests -only-test-configuration CI` runs, Then all 17 package test targets plus `OpenAgentsSnapshotTests` execute, `OpenAgentsUITests` does not, and the test process env contains `SNAPSHOT_TESTING_RECORD=never` (the snapshot canary passes against its committed baseline instead of re-recording). When the same plan runs with `-only-test-configuration Default`, Then no record env is set, so the swift-snapshot-testing default trait `.snapshots(record: .missing)` governs local first-run recording.
- Given the `OpenAgentsUITests` scheme, When `xcodebuild test … -testPlan UISmoke` runs, Then only `OpenAgentsUITests` executes (the M2-01 placeholder `SmokeTests.testPlaceholder`).

## Product and design spec

No end-user surface. The "product" is contributor and CI ergonomics. Entry points: `swift test --package-path ios/Packages/OpenAgentsTestSupport` (fast host loop), the `UnitTests` test plan on the `OpenAgents` scheme (default plan), and the `UISmoke` test plan on the new `OpenAgentsUITests` scheme. Primary flow: write a feature test in any package → import `OpenAgentsTestSupport` from that package's **test target only** → use the helpers. States: red/green test output and `.xcresult` bundles; there is no loading/empty/error UI. Copy: error descriptions on `FixtureLoaderError`/`TestHTTPServerError` must name the offending path/state (they are the operator-facing "copy"). Accessibility/permissions: n/a. Anti-requirement: helpers must never read wall-clock defaults invisibly — clocks, locales, and timezones are explicit (`FixedDateProvider`, `TestEnvironment.locale = en_US`, `TestEnvironment.timeZone = UTC`), per the determinism hygiene checklist in 06 §6.4.

Typed `enum FixtureLoaderError: Error, CustomStringConvertible { case resourceNotFound(relativePath: String, bundle: String), notUTF8(relativePath: String), emptySSEFile(relativePath: String) }`.
- `TestHTTPServer.swift` — `actor TestHTTPServer` wrapping FlyingFox: `func start() async throws -> UInt16` (always port 0; returns the assigned port), `var baseURL: URL` (`http://127.0.0.1:<port>`), `func stop() async`, `func registerJSON(_ method: String, _ path: String, status: Int = 200, body: Data)`, `func registerSSE(_ path: String, chunks: [Data], interChunkDelay: Duration = .milliseconds(25))` (responds with the two SSE headers above and writes chunks with the delay), `var receivedRequests: [RecordedRequest]` where `RecordedRequest` is `{ method, path, headers: [String: String], body: Data }` — the seam 06 §7.3 step 5 asserts against.

## Observability and user feedback

- Named module: `OpenAgentsTestSupport` (test-only). Hard rule: it never imports the `Observability` package and never logs to the app OSLog subsystem `com.openagents.app` — the six-category taxonomy in `docs/plans/ios-app/07-observability.md` §3 is reserved for app runtime, and polluting it would corrupt the `xcrun simctl … log show` evidence recipes used by every later slice. Enforcement grep (must return nothing): `grep -rn "import Observability\|import OSLog\|com.openagents.app" ios/Packages/OpenAgentsTestSupport/Sources/`.
- Typed error kinds (surface in Swift Testing failure output, the operator-facing channel for test infra): `FixtureLoaderError.resourceNotFound | .notUTF8 | .emptySSEFile` (each names the relative path) and `TestHTTPServerError.notStarted`. ## Regression risks and concerns

- `StubURLProtocol`'s static registry is shared mutable state: a suite that forgets `.serialized` or `reset()` can bleed stubs into parallel tests. Mitigation: the API doc-comments state the rule, the spike suite models it, and any future flake here follows the 06 §12 quarantine workflow.
- Timing assertions (≥ 100 ms gap with a 200 ms delay) could flake on heavily loaded CI machines. The 2× margin is deliberate; if a flake is ever observed, raise the delay to 500 ms/threshold 250 ms in the same-day flake fix — never delete the assertion, it is the entire point of the spike.
- Test-plan identifier drift: app-container target identifiers in `.xctestplan` change if `project.yml` targets are renamed/added. XcodeGen determinism keeps them stable otherwise; the re-extraction recipe is in the checklist and must be referenced in any M2+ PR that edits targets.
- Accidental linkage of FlyingFox/`OpenAgentsTestSupport` into an app or library graph would ship test code in release builds; the hygiene grep in the checklist is the review gate, and 03 §2.2's review rule applies.
- Running the `UnitTests` plan without `-only-test-configuration` executes both configurations (every test twice). Local docs in `ios/Fixtures/README.md` and the PR description must name `-only-test-configuration Default` for local full runs.
- The snapshot baseline is recorded on a local simulator before the CI runner exists (M2-03); if the runner's iOS 26.0 runtime renders the canary differently, re-record on the runner-matching runtime in the M2-03 PR per 06 §6.5 — trust CI, not the local machine.
