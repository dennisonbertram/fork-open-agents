## Why this matters

This is the foundation slice of the streaming milestone: a Swift decoder for every chunk shape `ai@6.0.168` emits on the UI Message Stream, proven against true server bytes. Every sibling issue consumes what lands here — M7-02's reducer applies `UIMessageChunk` values, M7-03's `ChatStreamClient` runs `parseSSELine` over `URLSession.AsyncBytes`, and the recorded fixtures become the deterministic regression corpus for the whole engine (goldens, replay-idempotence, perf, snapshots, and the XCUITest smoke all replay these exact files). If decoding is strict instead of lenient, the first server-side chunk-type addition bricks every live chat in the field; if fixtures are invented instead of recorded, the suite proves fidelity to our imagination instead of to `apps/web`. Protected path T3 (`docs/plans/ios-app/00-overview.md` section: top-level proofs): the SSE decoder decodes every chunk type emitted by `ai@6.0.168` against recorded fixtures, with unknown-type tolerance.

## User/operator path protected

T3 — every chunk type the server emits decodes against true server bytes, and unknown types are skipped, never fatal. Concretely: a user watching a live agent run keeps receiving rendered content even when the server team ships a new chunk `type` or a new `data-*` name mid-flight, and a malformed line injected by infrastructure skips one chunk instead of killing the stream. Operator side: when a decode problem does occur, the outcome surfaces as a countable skip (the seam M7-03 logs as `stream_protocol_violation`), never as a crash or a silently truncated transcript. Downstream protected paths fed by this slice: P3/P4/P5 per `docs/plans/ios-app/06-testing-strategy.md` section 2.

## Behavior contract

- Given the line `data: {"type":"text-delta","id":"text-1","delta":"Hello"}`, when `parseSSELine` runs, then it returns `.data("{\"type\":\"text-delta\",\"id\":\"text-1\",\"delta\":\"Hello\"}")` (single optional space after `data:` stripped, payload otherwise byte-exact).
- Given the line `data:{"type":"finish-step"}` (no space after the colon), when `parseSSELine` runs, then it returns `.data(...)` with the identical JSON — spacing is optional per the SSE spec.
- Given the line `data: [DONE]`, when `parseSSELine` runs, then it returns `.done`; given an empty line, a line starting with `:` (SSE comment, including the three metadata comments prepended to every fixture), or a line starting with `event:`/`id:`/`retry:`, then it returns `.ignore`.
- Given a line ending in a stray carriage return (`data: {...}\r`, as produced when a fixture file with CRLF endings is split on `\n` alone), when `parseSSELine` runs, then the trailing `\r` is stripped and the payload decodes identically to the LF case.
- Given each of the 26 example payloads in `docs/plans/ios-app/05-streaming-chat-engine.md` section 1.4 (copied into the test verbatim), when `UIMessageChunk(lenientlyDecoding:)` runs, then each returns the matching enum case with the documented fields populated — including `providerMetadata`/`input`/`output`/`data`/`messageMetadata` decoded as `OpenAgentsCore.JSONValue`, never `Any`.
- Given `{"type":"tool-output-available","toolCallId":"call_task1","output":{...},"preliminary":true}`, when decoded, then `.toolOutputAvailable(... preliminary: true)` — the same case as the final shape, distinguished only by the flag.
- Given `{"type":"data-workspace-status","id":"workspace-status","transient":true,"data":{...}}`, when decoded, then `.data(name: "workspace-status", id: "workspace-status", data: ..., transient: true)`; given `{"type":"data-never-seen-before","data":{"x":1}}`, then `.data(name: "never-seen-before", ...)` — the `data-` prefix family is open and decodes by prefix match, never by an allowlist.
- Given `{"type":"future-thing","payload":{"deep":[1,2]}}` (valid JSON, unknown discriminator), when decoded, then `.unknown(type: "future-thing")` — no throw, no nil.
- Given `{"type":"text-delta"}` (known discriminator, required `id`/`delta` fields missing), when decoded, then it degrades to `.unknown(type: "text-delta")` — field-level failures on known types must never throw or return nil; they degrade and are countable.
- Given the bytes `{"type":` (truncated/malformed JSON) or a payload that is not a JSON object with a string `type` field, when `UIMessageChunk(lenientlyDecoding:)` runs, then it returns `nil` — the caller's skip signal.
- Given fixture `04-multi-step-long-turn.sse.txt` served through `StubURLProtocol` in deterministic pseudo-random 1-64-byte slices (seeded RNG), when the byte stream is consumed line-by-line and decoded, then the resulting chunk sequence is element-for-element equal to decoding the same file as one whole buffer — payloads split across byte-chunk boundaries are reassembled losslessly.
- Given fixtures 01-13, when every `data:` payload line in each file is decoded, then zero lines return `nil` and zero decode to `.unknown` (these are raw captures of shapes we model); given fixture `14-unknown-chunk-types.sse.txt`, then exactly its injected malformed line returns `nil`, its injected `{"type":"future-thing"}` decodes to `.unknown`, and its injected `data-new-feature` decodes to `.data(name: "new-feature", ...)`.
- Given `grep -rEn "ghs_|gho_|vc_|Bearer " ios/Fixtures/` after this PR, when run from the repo root, then it prints nothing (sanitization proof).

## Product and design spec

Developer-facing slice; no end-user UI ships here. The "product" is the decoding API every engine layer consumes:

- Entry points: `parseSSELine(_:) -> SSELineEvent` and `UIMessageChunk(lenientlyDecoding: Data) -> UIMessageChunk?`, both `public`, both pure (no I/O, no clocks, no actors, no logging) so they are trivially host-testable and reusable by M7-02/M7-03 and by the fixture loader.
- States: `.ignore` / `.done` / `.data(String)` at the line level; a typed chunk, `.unknown(type:)`, or `nil` at the payload level. There is no error state — leniency is the contract; nothing here throws.
- Accessibility/copy/permissions: not applicable. Error presentation for stream failures is owned by M7-03 and `docs/plans/ios-app/07-observability.md` section 12.
- The fixture catalog is also a product for contributors: `ios/Fixtures/sse/README.md` documents, per fixture, the capture date, server git SHA, exact prompt used, whether it is `# SYNTHETIC`, and what each fixture must contain, so anyone can re-record when the contract evolves.

## Regression risks and concerns

- Over-strict decoding is the failure mode this slice exists to prevent: a closed `finishReason` enum, an exhaustive tool-name switch, or a throwing initializer would turn the next server-side addition into a field crash. The leniency tests pin the contract; reviewers must reject any `throw` reachable from `lenientlyDecoding`.
- Degrading known-type/missing-field payloads to `.unknown` silently drops content if the server ships a breaking field rename. Accepted trade-off (never fatal beats occasionally lossy); the skip counter plus fixture re-record policy is the detection path.
- Fixture loader mechanism: if M2-04's loader cannot reach `ios/Fixtures/sse` from the StreamEngine test target, the `#filePath` fallback must be used consistently with M3-02's choice — two different mechanisms across packages would be a maintenance trap; note the chosen mechanism in the PR.
- Fixture 04 (≥ 2,000 chunks) is a large text file; it is the perf corpus and must not be truncated "for tidiness." If it exceeds a few MB, note the size in the PR — do not introduce LFS unilaterally.
- Captures are nondeterministic (live LLM): must-contain assertions check structure, never exact text. If a capture misses a required element (e.g. no `data-pr` resolution), re-run the capture with an adjusted prompt rather than weakening the assertion.
- Synthetic escape hatch abuse: only 10/13 may fall back, only with a README reason and a filed re-record follow-up; 14 is synthetic by design. Anything else hand-edited is a review-blocking defect.
- BotID: capturing through a disabled or bypassed bot check in committed server code would poison the well for M1-07; the only acceptable local path is the documented test-auth cookie.
