## Why this matters

SCR-11 is how work gets created on iOS — without it the app is a read-only mirror. This issue builds the New Session sheet: a two-mode control (Agent Session / Chat Only) whose captions explain the difference in one line, a searchable repo picker with org filtering and private-repo locks, a branch picker that defaults to a safe auto-created branch so the agent never works directly on `main` (lesson B10), and a create call wired to `POST /api/sessions` with every documented failure mapped to specific, honest copy. Two web bugs are designed out up front: switching modes must never reset the repo selection (lesson B13), and no error may fail silently (lesson B4). The first-message handoff goes through a protocol seam so the streaming engine (M7) and composer (M8) can swap in later without touching this screen.

## User/operator path protected

P6 — a signed-in user with the GitHub App installed taps `+` in the Sessions inbox, picks a repository, keeps the default "New branch (auto)", types a prompt, taps **Start Session**, and lands in the new session's chat. Secondary: the same user on a flaky network or with an expired GitHub connection gets an explicit, recoverable error state instead of a dead button or a silent failure.

## Behavior contract

- Given the Sessions inbox (SCR-10), when the user taps the `+` nav-bar button, then the New Session sheet appears titled **"New Session"** with the mode control on **Agent Session** (caption: "The agent works on a repository in a cloud workspace."), an unselected repo picker row, a branch picker row showing **"New branch (auto)"**, an optional title field (placeholder "Session name (optional)", footer "Leave blank for a random name."), a multiline prompt field (placeholder "What should the agent do?") with a `mic` button, and a disabled **Start Session** button with footnote "Choose a repository to start."
- Given Agent Session mode with repo `acme/web` selected, when the user switches to **Chat Only** and back to **Agent Session**, then `acme/web` is still selected and the branch picker state is unchanged (lesson B13).
- Given **Chat Only** mode (caption: "Brainstorm without a repository. No workspace."), when the prompt field is empty, then the primary button reads **"Start Chat"**, is disabled, and shows footnote "Type a message to start."; when the prompt is non-empty, the button enables.
- Given the repo picker, when it opens, then `ui_screen_appeared screen=repo_picker` is logged, cached rows from the PersistenceKit `repo` table render immediately, and a refresh via `listInstallationRepos` replaces them; typing in search debounces 300 ms and re-queries with `query=` and `limit=50`; the org filter menu lists installations from `listInstallations` and scopes the request with `installation_id`; private repos show `lock.fill`; the list footer link **"Manage repository access"** invokes the injected escape-hatch closure.
- Given `getGitHubConnectionStatus` returns `status: "reconnect_required"`, when the repo picker renders, then an inline banner shows **"GitHub connection expired."** with a **"Reconnect"** button that invokes the injected reconnect closure (the web `?step=github` flow in `ASWebAuthenticationSession`, wired by AppShell).
- Given `listInstallationRepos` returns an empty array with no query, when the repo picker renders, then it shows **"No repositories. Connect GitHub or install the GitHub App on an organization."** with button **"Manage Access"** (same escape-hatch closure).
- Given a selected repo, when the branch picker opens, then `listBranches(owner:repo:limit: 50)` loads `{ branches, defaultBranch }`; the first row **"New branch (auto)"** is checked by default with caption "A new branch like mb/3f9a2c10 will be created — {defaultBranch} is untouched." (the `{defaultBranch}` clause renders only after `defaultBranch` arrives; before that the caption is "A new branch like mb/3f9a2c10 will be created."); searching filters via the `query=` parameter; picking an existing branch checks that row instead (lesson B10).
- Given a valid Agent Session form, when the user taps **Start Session**, then exactly one `POST /api/sessions` fires with `{ title?, repoOwner, repoName, cloneUrl, isNewBranch: true }` (auto branch) or `{ ..., branch: "<picked>", isNewBranch: false }` (existing branch), the button shows a labeled spinner "Starting…" and disables resubmission; on 200 the `{ session, chat }` response is upserted into the GRDB `session`/`chat` caches, the prompt is handed to `FirstMessageSending.sendFirstMessage(sessionId:chatId:text:)`, the sheet dismisses, and navigation pushes the session's chat (SCR-12).
- Given the server returns 400, when create fails, then an alert shows title **"Couldn't create the session."**, body = the server's `error` string (e.g. "Invalid repository owner"), buttons **"Try Again"** (re-submits) / **"Cancel"**, and `ui_error_presented error_kind=http_validation` is logged.
- Given the server returns 429 (limit 10/min), then the same alert shape shows body **"You're creating sessions too quickly. Wait a minute and try again."** (`error_kind=http_rate_limited`); the request is never auto-retried (mutations are in the no-retry class per `docs/plans/ios-app/02-api-contract-and-networking.md` section 4).
- Given the server returns 403 with body `{ "error": "Access denied" }` (BotID), then the alert body is **"Request blocked. Try again from this device in a moment."** (`error_kind=botid_blocked`); any other 403 message is shown verbatim as the alert body (`error_kind=http_forbidden`).
- Given the device is offline (`ConnectionState.offline`), when the sheet is visible, then the offline banner shows, every form control is disabled, the primary button footnote reads "You're offline. Reconnect to start.", and no request can fire (`error_kind=network_offline` if a request was in flight when the network dropped).
- Given Chat Only success, then the same create call fires with no repo fields, the server creates a no-sandbox session, and the identical success handoff runs with **Start Chat** semantics.

## Product and design spec

- **Entry points (already shipped by siblings, rewired here):** SCR-10 `+` button, SCR-10 invitation empty-state chips (prefill `prompt`), SCR-10 repo section-header context menu "New session in {repo}" (prefill repo), SCR-21 "New Session" button (prefill repo, lands with M7+ repo screens). `CreateSessionScreen` therefore accepts optional `prefilledRepo: Repo?` and `prefilledPrompt: String?` init parameters.
- **Layout (sheet):** title "New Session"; segmented `Picker` with "Agent Session" / "Chat Only"; directly beneath it one caption line (`Type.metadata`) showing the selected mode's description; Agent Session form: repo picker row (pushed list), branch picker row, title field; then the prompt field with `mic` (44 pt) inside the field's trailing edge; then the primary button. All copy strings are the exact ones in the Behavior contract — they are the contract.
- **Mic affordance stub:** the `mic` button focuses the prompt field (system keyboard dictation remains available) and logs `ui_action action=dictation_mic_tapped`. It is wired through `protocol DictationStarting` so M8-02 swaps in the `POST /api/transcribe` implementation without UI changes.
- **States:** repo list loading = skeleton rows; repo list empty / reconnect-required / offline per Behavior contract; submitting = labeled spinner "Starting…"; every disabled control exposes its reason as an inline footnote (lesson B7).
- **Accessibility (01-product-and-ux.md section 7.3):** the mode control's `accessibilityValue` carries the full selected caption; the disabled primary button exposes its footnote reason via `accessibilityHint`; all tap targets ≥ 44 pt; Dynamic Type to AX5 with no fixed heights; snapshot variants at `.large` and `.accessibility3`.
- **Permissions:** none beyond an authenticated session. No haptics on create (haptics budget belongs to send/run completion, `01-product-and-ux.md` section 3.7).

Cross-feature boundaries: `SessionsFeature` never imports `ChatFeature` or `SettingsFeature`. AppShell injects three closures/protocols into `CreateSessionStore`: `firstMessageSender: FirstMessageSending` (interim = draft stash; M7/M8 swap in the real send + S1), `onManageRepositoryAccess: () -> Void` (interim = open the GitHub App installation page — `installationUrl` from `listInstallations` when available, else the GitHub App install URL — in `ASWebAuthenticationSession`; M10-05 redirects this to SCR-43), and `onReconnectGitHub: () -> Void` (reuses M5-03's connect-GitHub web flow). Navigation on success goes through the typed `AppRouter`/`SessionsRoute` path from M5-02; the store exposes `onSessionCreated: (Session, Chat) -> Void`.

Data model: success upserts into the GRDB `session` and `chat` tables via the M6-01 cache APIs (confirm exact API names in `ios/Packages/PersistenceKit/Sources/PersistenceKit` — they are the same calls M6-02 uses for poll results), so the inbox shows the new session without waiting for the next poll.

## Observability and user feedback

Module: `SessionsFeature` logging through the injected `EventLogging` (never `Logger` directly), subsystem `com.openagents.ios`, categories `ui` (this slice) and `api`/`db` (emitted by APIClient/PersistenceKit for free). Events:

- `ui_screen_appeared` (info) `{ screen: "new_session" | "repo_picker" | "branch_picker" }`.
- `ui_action` (info) `{ action: "session_mode_switched" | "session_repo_selected" | "session_branch_selected" | "session_create_submitted" | "dictation_mic_tapped", screen: "new_session" }`; on success additionally `ui_action` `{ action: "session_create_succeeded", screen: "new_session", session_id, chat_id }`.
- `ui_error_presented` (notice) `{ error_kind, screen: "new_session", copy_key }` with typed `error_kind` values: `http_validation`, `http_rate_limited`, `botid_blocked`, `http_forbidden`, `network_offline`, `decode_failed`; copy keys: `error.session_create_failed`, `error.session_create_rate_limited`, `error.session_create_bot_blocked`, `status.connection.offline`.
- Correlation: the failing create joins to `api_request_failed { request_id, method: "POST", path: "/api/sessions", status, error_kind }` from the M3-01 middleware; include `session_id`/`chat_id` on all post-success events.
- Redaction: never log the prompt text, the session title, repo owner/name, or branch names (private-repo metadata is content) — log only counts (`repo_count`, `branch_count`) and ids. Query strings are never logged (07 section 4.2 rule).
- Debug recipes:
  - `xcrun simctl spawn booted log show --last 10m --predicate 'subsystem == "com.openagents.ios" AND category == "ui" AND composedMessage CONTAINS "new_session"'` — the screen's full event trail.
  - `log show --predicate 'subsystem == "com.openagents.ios" AND composedMessage CONTAINS "<request_id>"'` — join a presented error to its API failure.
  - Grep guard for the redaction rule in this package: `grep -rnE '\\\((prompt|title|repoOwner|repoName|branch)\)' ios/Packages/SessionsFeature/Sources` must return nothing inside logging calls.

## Regression risks and concerns

- The AppShell wiring edits the M6-02 inbox presentation — re-run `SessionsFeatureTests` in full and re-check the inbox snapshots so the `+` rewire does not regress SCR-10.
- The draft-stash interim sender writes `chatDraft` rows that M8-01's composer will later read as a real draft; keep the write idempotent (PK `chatId`) so a re-presented chat never duplicates the prompt. When M7/M8 swap in the real sender, the protocol signature must not change — it is the contract.
- 403 ambiguity: the server also 403s for Vercel-token branches ("Connect Vercel…", "Reconnect Vercel…"). iOS never sends `vercelProject`, so only "Access denied" should occur — but the mapping must still show unexpected 403 messages verbatim instead of mislabeling them as bot blocks.
- `isNewBranch: true` ignores any `branch` value server-side; never send both, or a future server tightening could 400.
- Repo cache staleness: GRDB `repo` rows are a short-TTL convenience (7-day pruning in M6-01); the picker must always refresh on open, and search must bypass the cache, or users will pick repos the App no longer has access to and hit create-time 400s.
- Rate limiting in tests: the manual 429 drill creates 10 real sessions on the local DB — use a throwaway local database, never preview/production.
- Strict-concurrency: `CreateSessionStore` is `@MainActor @Observable`; the facades are `Sendable` — any compiler diagnosis here must be fixed with isolation annotations, not `@unchecked Sendable`.
