## Why this matters

The Sessions inbox is the first signed-in screen and the triage home of the entire app: every session a user owns, grouped by repo, with live status. It is also the proving ground for the app's two core data promises — U2 (cold launch renders the inbox from GRDB in under 2 seconds, before any network response) and P9 (offline shows cached data with explicit staleness, never a blank screen). The `SessionListStore` built here is app-scoped and becomes the single source of truth for session metadata (lesson B15): later slices (chat header, tab badges, completion notices) read from it via GRDB observation instead of re-fetching. If this slice is wrong, every downstream M6/M7 screen inherits the wrongness.

## User/operator path protected

P2 (from `docs/plans/ios-app/06-testing-strategy.md` §2): a signed-in user opens the app, sees their session list instantly (cached rows render before the first network byte), watches it refresh in place, and taps a row to open that session. The offline variant of the same path: airplane mode shows the cached list plus an amber staleness banner instead of a spinner or a crash.

## Behavior contract

- Given a signed-in user with cached `session` rows in GRDB, When the app cold-launches to the Sessions tab, Then the list renders the cached rows immediately from `ValueObservation` (no skeleton, no spinner) and a network `refresh()` follows; the UI updates only via the observation when the fetch lands.
- Given a signed-in first-run user with an empty GRDB `session` table, When the Sessions tab appears, Then 8 skeleton rows show until `GET /api/sessions?status=active` resolves.
- Given the active fetch resolves with zero sessions, When the Active segment is shown, Then the invitation empty state renders: a focused mini-composer card titled "Start your first session", placeholder "Pick a repo and describe what to build…", and three suggestion chips — "Fix a failing test", "Explain this repo", "Start from a GitHub issue" — each invoking the `onCreate` navigation closure (SCR-11 with the prompt prefilled; the prefill string is passed through, the sheet itself is M6-03 scope).
- Given at least one cached session has `hasStreaming == true`, When the poll loop schedules the next tick, Then the interval is 3 s; given no session is streaming, Then it is 30 s; given `scenePhase != .active`, Then polling is paused entirely and resumes on foreground.
- Given sessions from repos `acme/web` and `acme/api` plus one repo-less (chat-only) session, When the list renders, Then rows group into sections headed `acme/web`, `acme/api`, and "No repository", sections ordered by their newest member's `lastActivityAt` descending, rows within a section ordered by `lastActivityAt` descending.
- Given a session with `hasStreaming == true`, When its row renders, Then the trailing status glyph is a pulsing `StatusRunning` dot; given `hasStreaming == false && hasUnread == true`, an `AccentPrimary` dot; given neither but `prStatus != nil`, an `arrow.triangle.pull` icon tinted `StatusSuccess` (open) / `AccentPrimary` (merged) / `StatusError` (closed); given none of these, no glyph. Exactly one glyph per row, in that precedence order.
- Given the active response includes `archivedCount: 5` and 12 active sessions, When the segmented control renders, Then it reads "Active 12" and "Archive 5".
- Given the user types "login" into the bottom-aligned search field, When filtering runs, Then only sessions whose `title` or `owner/repo` string contains "login" case-insensitively remain; given no match, the list shows "No sessions match “login”." (client-side filter; the server has no search param on `GET /api/sessions`).
- Given the user swipes a row trailing and picks Rename, When they submit a non-empty title, Then the row title updates immediately (optimistic GRDB write), `PATCH /api/sessions/{sessionId}` with `{ title }` fires, and the response `{ session }` write-through replaces the cached row; given the PATCH fails, Then the title reverts to the pre-edit snapshot and a toast "Couldn't rename. Try again." appears; given the submitted text is empty, Then the old name is kept and no request is sent.
- Given the user swipes a row leading and taps Archive, When the optimistic write runs, Then the row leaves the Active list immediately and `PATCH /api/sessions/{sessionId}` with `{ status: "archived" }` fires; given the server returns 409 (archive race) or any error, Then the row is restored from the snapshot, a toast "Couldn't archive. Try again." appears, and a `refresh()` reconciles. Unarchive mirrors this from the Archive segment.
- Given the Archive segment with more than 50 archived sessions, When the user scrolls to the bottom, Then the store requests `GET /api/sessions?status=archived&limit=50&offset={nextOffset}` and appends pages while `pagination.hasMore` is true; fetched rows are upserted into GRDB (never deleted by pagination); the Archive empty state reads "No archived sessions."
- Given the device is offline, When `refresh()` throws `APIError` with `error_kind=network_offline`, Then cached rows stay rendered, `freshness` becomes `.offline(since: <syncState.lastRefreshedAt>)`, and the amber `StatusWarning` banner "You're offline. Showing saved data." (copy key `status.connection.offline`) appears; pull-to-refresh in this state re-fails silently into the same banner, never an alert.
- Given a rename succeeds while another screen (e.g. a future SCR-12 chat header) observes the same session row via PersistenceKit, When the write-through lands, Then the second observer receives the new title from GRDB without any cross-store call (lesson B15: GRDB is the single source of truth for session metadata).
- Given GRDB is empty and the first fetch fails with a non-offline error, When the Active segment renders, Then the standard error card with a Retry button appears (never a blank screen), and `ui_error_presented` is logged.

## Product and design spec

- Entry point: root of the Sessions tab (tab 1, `bubble.left.and.bubble.right`), already hosted by AppShell's `NavigationStack` from M5-02. iPad regular width shows this screen as the `NavigationSplitView` sidebar (mechanics owned by M5-02; this screen must not assume column width).
- Layout: large title "Sessions"; segmented control Active | Archive with counts; `List` with repo-name section headers (`owner/repo`, `Type.metadata`); `.searchable(text:prompt:)` with prompt "Search sessions" (iOS 26 default bottom placement on iPhone); trailing nav-bar `+` button, 44 pt target, opening SCR-11 via the `onCreate` closure.
- Row anatomy: session title (`Type.sessionTitle`, `lineLimit(2)`), repo/branch line (`Type.metadata`), trailing column: relative time from `lastActivityAt` (`Type.timestamp`) + the single status glyph per the precedence rule in the behavior contract.
- Interactions: tap row → open session (SCR-12 destination; see Integration spec for the route). Swipe leading → Archive (`archivebox`) / Unarchive. Swipe trailing → Rename (inline `.alert` with a text field). Context menu: Rename, Archive/Unarchive, Copy Link (copies `{baseURL}/sessions/{sessionId}` — the web canonical URL), Share (system share sheet with the same URL). Repo section headers expose context-menu "New session in {repo}" (invokes `onCreate` with the repo preselected; the picker itself is M6-03). Pull-to-refresh with a `.selection` haptic at trigger — the only haptic on this screen (P6).
- States: Loading = 8 skeleton rows (only when cache is empty). Empty (Active) = the invitation empty state with the three chips. Empty (Archive) = "No archived sessions." Empty (search) = "No sessions match “{query}”." Error (no cache) = standard error card + Retry. Offline = cached list + amber banner "You're offline. Showing saved data."
- Color/typography: tokens only — `StatusRunning`, `AccentPrimary`, `StatusSuccess`, `StatusError`, `StatusWarning` for the banner; no hex, no `Font.system(size:)` (DesignSystem lint applies). Merged-PR purple is `AccentPrimary` (the closest of the twelve tokens; do not add a thirteenth).
- Accessibility (01 §7 row for SCR-10): each row's accessibility label combines title + repo + status word + relative time ("Fix login bug, acme/web, running, 2 minutes ago"); swipe actions are mirrored as custom accessibility actions; the streaming dot is exposed as the text "running", never visual-only. Dynamic Type up to AX3 must not truncate the title below 2 lines (snapshot-verified).
- Permissions: none. No new prompts of any kind.

## Integration spec

Server surfaces consumed (no server changes in this issue):

- `GET /api/sessions?status=active` — poll target; response `{ sessions: SessionSummary[], archivedCount }`. `SessionSummary` per `apps/web/lib/db/sessions.ts`: `{ id, title, status, repoOwner, repoName, branch, linesAdded, linesRemoved, prNumber, prStatus ("open"|"merged"|"closed"|null), createdAt, lastActivityAt, hasUnread, hasStreaming, latestChatId }`.
- `GET /api/sessions?status=archived&limit=50&offset={n}` — Archive pagination; response adds `pagination: { limit, offset, hasMore, nextOffset }`.
- `PATCH /api/sessions/{sessionId}` with `{ title }` or `{ status: "archived" | "active" }` — rename/archive/unarchive; response `{ session }` is written through to GRDB; errors 400/401/403/404/409.

All calls go through the existing `SessionsAPI` facade (`ios/Packages/APIClient`, M3-02) — no generated types above APIClient. If `SessionsAPI` lacks an archived-page method, add `listArchived(limit:offset:)` to the facade in this issue (facade addition, not a spec change; the routes are already in the OpenAPI spec from M1).

  - `ui_screen_appeared` — info, `{ screen: "sessions_list" }` on appear.
  - `ui_action` — info, `{ action, screen: "sessions_list", session_id }` for `session_open`, `session_rename`, `session_archive` (existing id), `session_unarchive`, `sessions_archive_page` (fields add `offset` for the page action).
  - `db_sync_applied` — info, `{ entity: "session", rows, duration_ms }` after each successful `replaceAll`/upsert batch (emitted by PersistenceKit per M6-01; verified observable here).
  - `ui_error_presented` — notice, `{ error_kind, screen: "sessions_list", copy_key }` for the error card, rename/archive failure toasts (`copy_key: "error.session_update_failed"`), and the offline banner (`copy_key: "status.connection.offline"`, `error_kind: "network_offline"`).
- Typed error kinds (07 §6 table, byte-identical strings): `network_offline`, `network_timeout`, `http_unauthorized`, `http_conflict` (409 archive race), `http_not_found`, `http_rate_limited`, `http_server_error`, `decode_failed`, `server_reported`. The store switches on `APIError`; it never invents new kinds.
- Correlation IDs: `request_id` (`ios.<uuidv4>`) is stamped per request by `RequestIDMiddleware`; `session_id` is included on every `ui_action` and mutation failure log. No `chat_id` applies on this screen.
- Redaction: session titles are user content — never logged at any level (log `session_id` only). Repo full names and branch names log only as `.private(mask: .hash)` per 07 §7.2. `path` fields are route templates (`/api/sessions/{sessionId}`), never concrete URLs or query strings. No `print(` anywhere.
- Debug recipes:
  - Live triage of inbox actions: `xcrun simctl spawn booted log stream --level info --predicate 'subsystem == "com.openagents.app" AND category == "ui"' | grep -E "session_archive|session_rename|sessions_list"`.
  - Poll cadence audit: `log show --predicate 'subsystem == "com.openagents.app" AND category == "api"' --last 5m | grep "/api/sessions"` — expect ~30 s gaps idle, ~3 s while a fixture session streams.
  - Server-side join during an incident: take a `request_id` from `api_request_failed`, then `grep '"requestId":"ios.<uuid>"' <server logs>` (the server echoes `x-request-id`).
- User-visible evidence: freshness is always explicit — the amber offline banner, skeletons only when the cache is empty, and reverted optimistic writes always produce a visible toast (never a silent snap-back). PR evidence: screenshots of populated/empty/offline states plus the log-stream capture.

## Regression risks and concerns

- **Cache wipe via unscoped replace**: polling `status=active` through an unscoped `replaceAll` deletes every archived row each 30 s tick — destroying offline archive reading. The scoped-replace test exists precisely for this; review the PersistenceKit diff against M6-01's `detailJson`-preservation rule too.
- **App-scoped store lifecycle**: `SessionListStore` outlives the screen. `.task`-based cancellation must not kill the app-scoped poll when the screen disappears, but `setScenePhaseActive(false)` must; get the ownership split (`activate()` idempotent, poll owned by the store, observation tied to store lifetime) right or polling silently dies after the first tab switch.
- **Optimistic revert races**: a poll tick landing between optimistic write and PATCH response can overwrite the optimistic title with the stale server copy (visible flicker, lesson-B15 class bug). Mitigation: write-through on response plus reconcile refresh on failure only; the rename tests pin the observable end states.
- **Battery/network burn**: a stuck `hasStreaming == true` row pins 3 s polling forever. The cadence is recomputed from the latest fetch each tick (test-pinned), and backgrounding always pauses.
- **iPad split-view assumptions**: this screen is the sidebar on regular width; hardcoding compact-only layout breaks M5-02's split view. Keep layout width-agnostic; the `ipad` snapshot variant is optional here but the screen must not crash in the sidebar.
- **A11yID drift**: the UITest smoke queries `session-list.root`/`session-list.row.<id>`; renaming them breaks the nightly smoke. The constants are already pinned — attach, don't rename.
- **Haptic/empty-state scope creep**: exactly one `.selection` haptic; the invitation empty state must not pre-prompt for any permission (01 §8).
