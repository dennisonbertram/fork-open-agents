## Why this matters

Every authenticated iOS feature — sessions, chat streaming, settings, repos — rides on one credential: the better-auth signed bearer token (`<token>.<sig>`). M0-01 made the server mint it (OTT verify → `set-auth-token` header) and M3-01 built the `AuthMiddleware` that attaches it, but nothing on the device can yet *obtain* or *keep* that token. This slice delivers the two custody primitives the whole M4 milestone is named for: a `KeychainTokenStore` actor that is the sole reader/writer of token material (device-bound, never iCloud-synced, survives relaunch), and a `SignInCoordinator` that runs the full Vercel OAuth dance — `POST /api/auth/sign-in/social` → `ASWebAuthenticationSession` → `openagents://auth?ott=…` → `POST /api/auth/one-time-token/verify` → Keychain. Without it, M4-02 (Apple), M4-03 (AuthController), and M5-03 (onboarding screens) have nothing to wire to. The slice also enforces the `04-auth.md` §11 security rules at the layer where a leak would be born: no token material in any log, cookie-free URLSessions, redacted callback URLs.

## User/operator path protected

P1 (`docs/plans/ios-app/06-testing-strategy.md` §2): a user signs in with Vercel OAuth and the resulting bearer token lands in the Keychain, where it authenticates `GET /api/auth/info` (response `user != nil`) and survives process relaunch. Secondary invariant protected: the token value never appears in any log, crash breadcrumb, or exported diagnostic at any level.

## Behavior contract

- Given a reachable server with M0-01 deployed, When `SignInCoordinator.signInWithVercel()` runs and the user completes the Vercel dance, Then the coordinator (1) obtained the authorize URL from `POST {baseURL}/api/auth/sign-in/social` with body `{"provider":"vercel","callbackURL":"/api/native-auth/complete","errorCallbackURL":"/api/native-auth/complete","disableRedirect":true}`, (2) received `openagents://auth?ott=<ott>` from the browser session, (3) exchanged it via `POST {baseURL}/api/auth/one-time-token/verify` with body `{"token":"<ott>"}`, and (4) stored the `set-auth-token` response header value **verbatim** in the Keychain via `AuthTokenStore.update(token:)`.
- Given a stored token, When a new `KeychainTokenStore` instance is created (simulating relaunch) and `currentToken()` is called, Then it returns the same string.
- Given the stored Keychain item, When its attributes are queried, Then `kSecClass` is `kSecClassGenericPassword`, `kSecAttrService` is `"com.openagents.ios.auth"`, `kSecAttrAccount` is `"session-token"`, `kSecAttrAccessible` is `kSecAttrAccessibleAfterFirstUnlockThisDeviceOnly`, and `kSecAttrSynchronizable` is absent or false.
- Given the user dismisses the sheet or cancels at Vercel's consent screen, When `ASWebAuthenticationSession` completes with `ASWebAuthenticationSessionError.canceledLogin`, Then the coordinator throws `AuthError.userCancelled`, nothing is stored, and no error-level event is logged (silent cancel; `auth_signin_cancelled` at notice).
- Given a callback `openagents://auth?error=access_denied`, Then the coordinator throws `AuthError.userCancelled` (same silent-cancel treatment).
- Given a callback `openagents://auth?error=sign_in_failed` (or any other error code), Then the coordinator throws `AuthError.serverRejected(code: "sign_in_failed")`.
- Given a callback with the wrong scheme or host, or with no `ott`/`error` query item, or an empty `ott` value, Then the coordinator throws `AuthError.unexpectedCallback`/`AuthError.missingToken`; any logged URL representation is `url.redactedForLogging` (query values stripped, names kept: `openagents://auth?ott=<redacted>`).
- Given the verify endpoint returns a non-200 status, or 200 without a `set-auth-token` header, Then the coordinator throws `AuthError.tokenExchangeFailed(status:)` and the Keychain is untouched.
- Given any response observed by the M3-01 `AuthMiddleware` carrying a `set-auth-token` header while `KeychainTokenStore` is the live `AuthTokenStore`, Then the Keychain item is replaced with the new value and the next request carries `Authorization: Bearer <new value>` (rotation contract, `04-auth.md` §8.5/§3.9).
- Given the Keychain write fails (non-`errSecSuccess`/`errSecItemNotFound` OSStatus), Then `update(token:)` throws `AuthError.keychain(status)` and `auth_token_persist_failed` is logged at fault with the integer `keychain_status` — never the token.
- Given any request issued by `SignInCoordinator`, Then it carries no `Cookie` header and accepts no cookies (ephemeral, cookie-disabled `URLSessionConfiguration` per `04-auth.md` §8.2), and both auth POSTs carry `Origin: openagents://` and `Content-Type: application/json`; the verify POST carries no `Authorization` header.
- Given the server's `{"url": …}` response contains a string that is not a valid URL, Then the coordinator throws `AuthError.malformedAuthorizeURL` before presenting any browser session.

## Product and design spec

This slice ships **no screens** — the sign-in UI is M5-03 (`OnboardingFeature.SignInScreen`) and the state machine that drives it is M4-03. The product surface here is the system-provided browser sheet plus the public `AuthKit` API the siblings consume.

- Entry point: `SignInCoordinator.signInWithVercel()` (public, `@MainActor`). Callers later: `AuthController.signInWithVercel()` (M4-03), `SignInScreen` (M5-03).
- Primary flow: iOS shows the standard `ASWebAuthenticationSession` consent alert ("'Open Agents' Wants to Use 'vercel.com' to Sign In"), then a Safari sheet on the Vercel authorize URL. `prefersEphemeralWebBrowserSession = false` so a user already signed into vercel.com in Safari gets near-instant SSO. `callback: .customScheme("openagents")` (iOS 17.4+ API; fine on iOS 26). The sheet dismisses itself when the `openagents://` redirect is intercepted; the ephemeral cookie jar dies with the sheet.
- States: in-flight (browser sheet visible; caller may show its own progress), success (method returns; token stored), silent cancel (`AuthError.userCancelled` — callers must render nothing), failure (typed `AuthError` — human copy and `error.*` copy keys are owned by `01-product-and-ux.md`/M5-03, not this slice).
- Accessibility: the sheet is system UI (fully accessible); no custom UI to audit.
- Permissions: none (no entitlement changes; the SIWA entitlement is M4-02). The `openagents` URL scheme is already registered in `ios/App/project.yml` `CFBundleURLTypes` by M2-01 — verify, add only if missing.
- Error/empty/loading behavior: errors are thrown values, never rendered here; there is no empty state; loading is the system sheet.

## Integration spec

New/edited files (all paths exact):

- `ios/Packages/AuthKit/Sources/AuthKit/KeychainTokenStore.swift` — `public actor KeychainTokenStore: AuthTokenStore`. `public init(service: String = "com.openagents.ios.auth", account: String = "session-token")` (injectable for test isolation). Implements `currentToken()` via `SecItemCopyMatching` (`kSecReturnData`, `kSecMatchLimitOne`), `update(token:)` via `SecItemUpdate` falling back to `SecItemAdd` on `errSecItemNotFound` (the add dictionary sets `kSecAttrAccessible = kSecAttrAccessibleAfterFirstUnlockThisDeviceOnly` and never sets `kSecAttrSynchronizable`), `clear()` via `SecItemDelete` — exactly the §8.3 listing, renamed to the protocol methods.
- `ios/Packages/AuthKit/Sources/AuthKit/AuthError.swift` — `public enum AuthError: Error, Equatable, Sendable` with cases `malformedAuthorizeURL`, `emptyCallback`, `unexpectedCallback(String)` (payload is the **redacted** URL string), `userCancelled`, `serverRejected(code: String)`, `missingToken`, `tokenExchangeFailed(status: Int)`, `keychain(OSStatus)`.
- `ios/Packages/AuthKit/Sources/AuthKit/CallbackParser.swift` — `static func parseOneTimeToken(from url: URL) throws -> String` per `04-auth.md` §8.2: scheme must be `openagents`, host `auth`; `error=access_denied` → `userCancelled`; other `error=` → `serverRejected(code:)`; missing/empty `ott` → `missingToken`; structural mismatch → `unexpectedCallback(url.redactedForLogging)`.
- `ios/Packages/AuthKit/Sources/AuthKit/WebAuthenticationPresenting.swift` — `public protocol WebAuthenticationPresenting: Sendable { func authenticate(url: URL, callbackScheme: String) async throws -> URL }` plus the production `SystemWebAuthenticationPresenter` wrapping `ASWebAuthenticationSession` in a `withCheckedThrowingContinuation`, owning the `ASWebAuthenticationPresentationContextProviding` anchor (resolve the key window), `prefersEphemeralWebBrowserSession = false`. This seam exists so unit tests simulate the browser dance.
- `ios/Packages/AuthKit/Sources/AuthKit/AuthURLSession.swift` — factory for the cookie-free session: `URLSessionConfiguration.ephemeral` with `httpCookieStorage = nil`, `httpShouldSetCookies = false`, `httpCookieAcceptPolicy = .never` (§8.2; rationale: a stray cookie on a `/api/auth/*` POST without `Origin` turns on better-auth origin validation → 403 `MISSING_OR_NULL_ORIGIN`).
- `ios/Packages/AuthKit/Sources/AuthKit/SignInCoordinator.swift` — `@MainActor public final class SignInCoordinator` with `public init(baseURL: URL, tokenStore: any AuthTokenStore, presenter: any WebAuthenticationPresenting, urlSession: URLSession)` and `public func signInWithVercel() async throws`. Steps per `04-auth.md` §8.1/§4: social POST (decode `{ url: String, redirect: Bool }` leniently), browser dance via the presenter, callback parse, OTT verify POST capturing `set-auth-token`, `tokenStore.update(token:)`. Both POSTs set `Origin: openagents://`; the verify POST sends no `Authorization`. Keep the OTT exchange in an internal `exchange(ott:)` method so the live-proof test can drive it directly.
- `ios/Packages/Observability/Sources/Observability/URLRedaction.swift` — `public extension URL { var redactedForLogging: String }`: keeps scheme/host/path and query-item **names**, replaces every query value with `<redacted>`, drops fragments and userinfo (`04-auth.md` §11.1). Lives in `Observability` so `AuthKit`, `APIClient`, and `StreamEngine` all share it.
- `ios/Packages/AuthKit/Package.swift` — MainActor-default template (`03-architecture.md` §4.1), platforms iOS-only, target deps `OpenAgentsCore` + `Observability`; **test target only** additionally depends on `APIClient` and `OpenAgentsTestSupport` (no production `AuthKit → APIClient` edge; the shared seam stays `AuthTokenStore`).

Routes consumed (server is untouched; all landed in M0-01): `POST /api/auth/sign-in/social`, `POST /api/auth/one-time-token/verify`, and `GET /api/auth/info` (live proof only). Data model: none. Events/observability: section below. Config: none — no new env vars, entitlements, or Info.plist keys. Compatibility: `AuthKit` is iOS-only, so its tests run on the simulator via `xcodebuild`, not host `swift test`; `Observability` stays host-runnable.

## Observability and user feedback

Named module: `AuthKit` logging through the `Log.auth` `os.Logger` (subsystem from `AppLog`, category `auth`) shipped by M2-01 in `ios/Packages/Observability`. Event names, levels, and snake_case fields are taken verbatim from `docs/plans/ios-app/07-observability.md` §4.1 so the M11-01 emitter migration is a find-and-replace:

- `auth_signin_started` (notice): `flow=vercel_oauth`, `request_id` (format `ios.<lowercase-uuidv4>`, generated via the existing `RequestID` helper and sent as `x-request-id` on both auth POSTs).
- `auth_signin_succeeded` (notice): `flow`, `duration_ms`.
- `auth_signin_cancelled` (notice — never error): `flow`.
- `auth_signin_failed` (error): `flow`, `error_kind`, `duration_ms`.
- `auth_token_rotated` (notice): `source=set_auth_token_header` — never the token value.
- `auth_token_persist_failed` (fault): `keychain_status` (OSStatus int), `error_kind=auth_keychain_failed`.

Typed `error_kind` values produced by this slice (taxonomy in `07-observability.md` §6): `auth_signin_cancelled` (cancel/`access_denied`), `auth_keychain_failed`, `server_reported` (other `error=` callback codes; the code rides in `server_error_kind`), `http_unexpected_status` (verify non-200 or missing `set-auth-token`), `decode_failed`, `network_offline`/`network_timeout`. One **new** kind is added to the §6 table and the `APIErrorKind` enum in this same PR: `auth_callback_invalid` (wrong scheme/host, missing/empty `ott`).

Correlation: `request_id` on every event for the two POSTs; no `session_id`/`chat_id` exists yet at sign-in time (out of scope by definition).

Redaction rules (binding, `04-auth.md` §11): never interpolate the bearer token, `set-auth-token` value, `Authorization` header, OTT, or raw callback URL into any log, breadcrumb, or error payload at any level; URLs are logged only via `redactedForLogging`; OSLog string fields default `.private` except the §7.2 public classes (`event`, `flow`, `error_kind`, `request_id`, statuses, durations). PR must attach the §11.7 grep proof (exact commands in the checklist).

User-visible status: none in this slice beyond the system browser sheet; typed `AuthError` values are the contract that M4-03/M5-03 render with `error.*` copy keys.

## Regression risks and concerns

- **Token-custody invariant**: `KeychainTokenStore` must remain the sole reader/writer of token material (`04-auth.md` §10) — no caching of the token in `SignInCoordinator` fields, `UserDefaults`, or logs. The grep proof and file 2 pin this.
- **Wrong Keychain accessibility class** would either break background networking (`WhenUnlocked`) or sync the session via iCloud (missing `ThisDeviceOnly`); file 2's attribute assertions are the guard. Note `kSecAttrAccessible` is only set on the `SecItemAdd` path — the test must assert after a fresh add.
- **Cookie leakage**: if any auth request rides a session with a cookie jar, better-auth's origin validation can 403 the dance intermittently. The configuration test in file 3 plus the `Origin: openagents://` belt-and-braces header prevent it.
- **Scheme hijack**: any app can claim `openagents://`; exposure is bounded to the single-use 3-minute OTT (accepted v1 posture, §11.5). Do not "improve" this with tokens in URLs.
- **M3-01 drift**: if the `AuthTokenStore` method names or the APIClient stub seam differ from this plan, adapt to what shipped (discovery step) rather than introducing a parallel protocol — two token stores would be a custody regression.
- **Strict concurrency traps**: `ASWebAuthenticationSession`'s completion handler must resume the continuation exactly once; the presenter is `@MainActor`-bound (AuthKit is MainActor-default per `03-architecture.md` §4.1) while `KeychainTokenStore` is an actor — keep `Sendable` conformances honest, no `@unchecked`.
- **Test pollution**: Keychain suites not marked `.serialized` or using the production service name would flake or clobber a developer's real token on their simulator.
- **iOS-only package gotcha**: adding `AuthKit` as a dependency of any host-runnable package (e.g. `APIClient`) would break macOS `swift test`; the rotation test therefore lives in `AuthKitTests` with a test-target-only `APIClient` dependency (no cycle: `APIClient` never imports `AuthKit`).

## Deploy or migration impact

None server-side: zero `apps/web` changes, no DB migration, no env vars, no OpenAPI regeneration (the better-auth endpoints used here are deliberately outside the generated client per `03-architecture.md` §3.4). No app is shipped yet — this lands as library code gated by `ios-ci.yml`; no entitlement, signing, or App Store impact (the SIWA entitlement arrives in M4-02). Rollback is a plain revert; Keychain items written by test runs use the throwaway test service name. The live proof requires a preview deployment of `develop` containing M0-01 — if none exists, deploy one first or note the blocker in the PR.
