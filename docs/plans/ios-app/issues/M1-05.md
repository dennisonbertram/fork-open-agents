## Why this matters

The iOS app's Settings, Model Picker, Usage, and Chat-composer surfaces (voice dictation, auto-titling) are all driven by the generated Swift client in `ios/Packages/OpenAgentsAPI`. Today `apps/web/openapi.json` documents only 6 paths / 10 operations, so none of these screens can be built against typed, drift-gated contracts. This batch adds the 35 settings/models/usage/misc operations from `docs/plans/ios-app/02-api-contract-and-networking.md` §2.3 Batch E to `buildOpenApiDocument()` in `apps/web/lib/api/openapi-spec.ts`, reusing the route-owned Zod schemas so the published contract cannot drift from the handlers. Without this, iOS milestone M3-03 (settings/models/usage facades) and M8-02 (voice dictation) are blocked.

## User/operator path protected

The preferences/models/usage contracts behind iOS settings are spec-covered and drift-gated: an iOS client generated from `apps/web/openapi.json` can read and update user preferences, list the model catalog, read usage and rank, manage agent settings, tool-entry approvals, model variants, runtime profiles, Composio profiles, and inference profiles, and call generate-title/transcribe — and any server change to those shapes turns `bun run --cwd apps/web openapi:check` or `apps/web/lib/api/openapi-spec.test.ts` red before it can ship silently.

## Behavior contract

- **Given** Batch A (M1-01) is merged, **when** `buildOpenApiDocument()` runs, **then** the document contains all 35 Batch E operationIds (table below), every schema is registered under its §2.2 stable name in `components.schemas`, and no schema contains `additionalProperties: false`.
- **Given** a session-authenticated request, **when** `GET /api/settings/preferences` returns 200, **then** the body matches the registered `UserPreferences` schema (`{ preferences: { defaultModelId, defaultSubagentModelId, defaultInferenceProfileId, defaultSandboxType, defaultManagedRuntimeProfileId, defaultDiffMode, autoCommitPush, autoCreatePr, alertsEnabled, alertSoundEnabled, publicUsageEnabled, globalSkillRefs, modelVariants, enabledModelIds, composioAgentDefaults } }` per `apps/web/lib/db/user-preferences.ts`).
- **Given** a valid partial body, **when** `PATCH /api/settings/preferences` succeeds, **then** it returns 200 `{ preferences }` with the merged row; **given** an invalid field (e.g. `defaultSandboxType: "qemu"`), **then** it returns 400 `{ error: string }` with the same field-specific message the route produces today (extraction must not change messages or status codes).
- **Given** no auth at all, **when** `GET /api/models` is called, **then** it returns 200 `{ models: AvailableModel[] }` — this operation declares `security: []` and joins the `publicOperationIds` allowlist in `apps/web/lib/api/openapi-spec.test.ts`; every other Batch E operation documents a 401.
- **Given** only `from` is supplied, **when** `GET /api/usage?from=2026-01-01` is called, **then** it returns 400 (both-or-neither rule, `apps/web/app/api/usage/_lib/query-range.ts`); with both params or neither it returns 200 `{ usage, insights, domainLeaderboard }`.
- **Given** a user with no eligible domain, **when** `GET /api/usage/rank` is called, **then** it returns 200 with the JSON body `null` — the spec documents the 200 response schema as a nullable object (`UsageRankResponse` with `nullable: true`), not an error.
- **Given** a base64 audio body over 10 MiB, **when** `POST /api/transcribe` is called, **then** it returns 413; a missing `audio` field returns 400; 5 requests/min per user returns 429 — all documented per-operation.
- **Given** a `PATCH /api/settings/agents` with omitted optional fields, **then** the operation `description` states the full-row-replace semantics (omitted fields reset to null) so the generated Swift client's call sites are warned.
- **Given** any inference-profile response, **then** the registered `SafeInferenceProfile` schema has **no** `apiKey` property — the key never round-trips.
- **Given** the spec is edited without regenerating, **when** `bun run --cwd apps/web openapi:check` runs, **then** it exits 1 with the regenerate instruction (drift gate).

## Product and design spec

Server-only contract work; no UI ships in this issue.

- **Entry point:** `apps/web/openapi.json` and `apps/web/lib/api/openapi-types.ts`, consumed by the iOS codegen pipeline (`ios/scripts/generate-openapi-client.sh`, M2-02) and by `openapi-fetch` via `apps/web/lib/api/client.ts`.
- **Primary flow:** spec authors add operations to `buildOpenApiDocument()`; consumers regenerate clients.
- **States/copy:** operation `summary`/`description` strings are the product surface — every operation gets a one-line summary; semantic gotchas (agents full-row replace, usage both-or-neither, rank nullable 200, transcribe size cap, Composio `redirectUrl` must be opened in a browser session with `callbackUrl: "openagents://composio-callback"`) go in `description`.
- **Permissions:** global `security` (bearerAuth + cookieAuth from M1-01) applies; only `listModels` overrides with `security: []`.
- **Error/empty/loading:** all non-2xx bodies documented as the registered `ErrorResponse` (`{ error: string }`); `reviewToolEntry` and `updateAgent` 400s may include a `details` field (flattened Zod error) — document `details` as an optional loose object on those operations.
- **Accessibility:** N/A (no UI).

- **Data model:** none. No Drizzle schema or migration changes (the `usage_events.source` enum is M1-07's scope).

- **Known serialization hazard:** `modelVariantSchema` embeds `providerOptionsSchema = z.record(z.string(), jsonValueSchema)` where `jsonValueSchema` is recursive (`apps/web/lib/model-variants.ts`). If `z.toJSONSchema(..., { target: "openapi-3.0" })` throws or emits unsupported `$defs` cycles, declare a spec-local loose `providerOptions: { type: "object" }` for the registered `ModelVariant` response schema and keep the real Zod schema for route validation only. ## Observability and user feedback

This slice changes contracts and validation plumbing, not runtime behavior, so the primary observability is the gate evidence; route logging stays exactly as-is (`console.error` in the catch paths of usage/models/transcribe routes is untouched).

- **Named gates (the evidence):** `apps/web/scripts/check-openapi.ts` exits 0 printing `✓ openapi.json is in sync with openapi-spec.ts`; `apps/web/lib/api/openapi-spec.test.ts` enforces unique operationIds, the documented 401 (minus `publicOperationIds`), and the new Batch E coverage test; both run inside `bun --bun run ci`.
- **Error kinds (contract level):** every non-2xx is the typed `ErrorResponse` `{ error: string }`; `updateAgent`/`reviewToolEntry` 400s add optional `details`. These map to the iOS `errorKind` taxonomy in `docs/plans/ios-app/07-observability.md` §6 (`http_validation` 400, `http_unauthenticated` 401, `http_forbidden` 403, `http_not_found` 404, `http_payload_too_large` 413, `http_rate_limited` 429) — the spec's documented status codes per operation are the source the client maps from, so omitting a documented 413/429 here is an observability defect on the phone.
- **Correlation:** these routes carry no `requestId` today; iOS sends `x-request-id: ios-<uuid>` (M3-01) which Vercel request logs index. No new server fields in this slice.
- **Redaction rules:** `SafeInferenceProfile` must never include `apiKey` (asserted by the red test); the transcribe `audio` base64 payload and `generate-title` `message` content must never appear in spec examples, test fixtures, or logs added by this PR; Composio `redirectUrl` values in contract-test output are fine (they are user-facing), but never log Composio auth-config secrets.
- **Debug recipes:**
  - `jq '.paths | keys' apps/web/openapi.json` — confirm the 19 Batch E paths are present.
  - `jq '[.paths[][] | objects | .operationId] | length' apps/web/openapi.json` — operation count (10 pre-existing + 35 from this batch + sibling batches).
  - `grep -c '"additionalProperties": false' apps/web/openapi.json` — must print `0`.
  - `curl -s -H "Cookie: open_agents_test_user_id=<TEST_AUTH_USER_ID>" http://localhost:3000/api/settings/preferences | jq .preferences` — live-shape spot check against a dev server (`OPEN_AGENTS_ENABLE_TEST_AUTH=1`).

## Regression risks and concerns

- **Preferences PATCH behavior drift:** replacing manual per-field checks with Zod could change error messages or start rejecting payloads with unknown extra fields the web UI sends. Mitigate: non-strict `z.object` (strips unknown keys), per-field `message` strings copied from the route, keep the `isManagedRuntimeProfileId` check, and the existing `route.test.ts` must pass unmodified.
- **Spec scripts importing server-only modules:** `openapi-spec.ts` must import only the `lib/` schema files, never `route.ts` modules — `apps/web/app/api/settings/runtime-profiles/route.ts` and friends pull `server-only`/DB imports that would break `bun run scripts/generate-openapi.ts`. The relocation step exists precisely to avoid this; verify `openapi:generate` runs standalone.
- **Recursive Zod schemas:** `jsonValueSchema`/`providerOptionsSchema` may not serialize under `z.toJSONSchema` openapi-3.0 — use the documented loose-object fallback rather than changing the route schemas.
- **Nullable top-level 200 (`getUsageRank`):** confirm Zod emits `nullable: true` (OpenAPI 3.0 style) for `.nullable()` object schemas; swift-openapi-generator must produce an optional payload. If serialization is wrong, hand-declare the JSON schema for this one response.
- **Largest batch:** 35 operations in one diff invites review fatigue and `ErrorResponse` copy-paste typos; the schema-registry collision error from M1-01 (`OpenAPI schema name collision`) is the backstop — never rename a registered schema to dodge it without a migration note.
- **Field freeze:** after iOS M3-03 consumes these shapes, response changes must be additive (`06-testing-strategy.md` §8.4); flag this in the PR body so later server work knows.

## Deploy or migration impact

None beyond a normal web deploy. No Drizzle migration, no new env vars, no Vercel config change. `apps/web/openapi.json` and `apps/web/lib/api/openapi-types.ts` are committed build artifacts — preview and production deploys are unaffected at runtime (the spec route, if served, simply exposes more paths). Route validation swaps are behavior-preserving, so shipped web clients see no difference. Rollback is a plain revert of the PR.
