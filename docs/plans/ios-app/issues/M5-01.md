## Why this matters

Every screen in milestones M5–M13 is specified against named tokens (`OAColor.*`, `OATypography.*`, `OASpacing.*`, `OARadius.*`) and four shared components. If this package is wrong, every later snapshot baseline, every status surface, and every accessibility audit inherits the defect. This slice makes the design rules from `docs/plans/ios-app/01-product-and-ux.md` section 3 *executable*: the 12 custom colors become asset-catalog tokens with a WCAG-AA contrast unit test in both light and dark mode, the Liquid Glass usage map gets its single sanctioned custom-glass wrapper, and the token-discipline rule ("no hex, no `Font.system(size:)`, no `Color(red:)` outside this package") becomes a CI grep-lint instead of a review hope. It is also the groundwork for protected path U8 (`docs/plans/ios-app/00-overview.md`): status is always icon + word + color, never color alone.

## User/operator path protected

U8 groundwork. A developer (human or agent) building any later screen consumes design primitives by token name only — `OAColor.statusError`, `OATypography.code`, `OASpacing.md` — and renders status through components that structurally pair glyph + word + color. An operator reviewing any later PR gets a hard CI failure (`ios/Scripts/ci.sh` via `ios/Scripts/token-lint.sh`) the moment feature code smuggles in a hex value, a point-size font, or an RGB literal. A user with Increase Contrast needs or dark mode active gets text that always meets WCAG AA against its documented background, proven by a unit test on every PR.

## Behavior contract

- Given the DesignSystem package with `Resources/Colors.xcassets` populated, When `OAColor.resolvedUIColor(_:style:)` resolves each of the 12 tokens for `.light` and `.dark`, Then every token returns a non-nil color and every (foreground, background) pair in the contrast table below meets its threshold in both modes (`ColorContrastTests` green).
- Given a missing or misnamed color set (error case), When `ColorContrastTests` runs, Then the test fails with a message naming the token and the mode (e.g. `"StatusWarning (light): asset not found"`) — it never crashes the test process and never silently passes.
- Given the `DesignSystemGallery` view, When `DesignSystemGallerySnapshotTests` runs on the pinned simulator, Then every gallery section matches its committed baseline in the canonical and `dark` variants; a layout change produces a failing diff image in the `.xcresult`, never a silent re-record (CI sets `SNAPSHOT_TESTING_RECORD=never`).
- Given a clean tree, When `./ios/Scripts/token-lint.sh` runs, Then it exits 0 and prints `✓ token lint passed`.
- Given `let bad = Color(red: 1, green: 0, blue: 0)` added to any Swift file outside `ios/Packages/DesignSystem` (error case), When `./ios/Scripts/token-lint.sh` runs, Then it exits 1 and prints the offending `file:line`, and `./ios/Scripts/ci.sh` therefore fails.
- Given `StatusDot(status: .running, label: "Running")`, When rendered, Then it shows a `statusRunning` dot pulsing opacity 1.0↔0.4 at 0.8 Hz, exposes accessibility label "Running" (never visual-only), and renders a static full-opacity dot when `accessibilityReduceMotion` is on (edge case).
- Given `GlassComposerContainer`, When rendered around opaque content, Then it applies exactly one `GlassEffectContainer` with `.glassEffect(.regular, in: .rect(cornerRadius: OARadius.composer))` and exposes a `glassEffectID` morph seam; it never nests glass inside glass (P1 — doc-comment contract plus gallery evidence; Reduce Transparency adaptation comes free from the system API, never a faked blur).
- Given a pinned proposal hex that fails its contrast threshold (edge case — several are precomputed to fail; see Integration spec), When implementing, Then the *value* is tuned the minimum distance to pass and the threshold is never lowered; the final hex is recorded back into `docs/plans/ios-app/01-product-and-ux.md` section 3.2 in the same PR.

## Product and design spec

No end-user screen ships; the product surface is the `DesignSystemGallery` (a `#Preview`-able, snapshot-tested scrolling catalog) and the components later screens compose.

- **Entry point:** `DesignSystemGallery` via Xcode previews and `DesignSystemGallerySnapshotTests`. Sections in fixed order: Colors (12 labeled swatches, asset name + hex caption), Typography (one sample line per token), Spacing & Radius (labeled bars/rounded rects), StatusDot (all four statuses with words), PillLabel (text-only, icon, numeric/monospaced-digit, tinted), EmptyStateView (sample with CTA), GlassComposerContainer (placeholder field + buttons over a text background so refraction context exists).
- **Components and copy:** components carry no hardcoded product copy; all strings are caller-supplied (gallery uses neutral samples like "Running", "No items yet", "$0.34"). `EmptyStateView` enforces the section 4.0 empty-state shape: one SF Symbol at symbol scale (no art), one title, one sentence, at most one primary CTA button (44 pt min target).
- **States:** `StatusDot` covers `running` (pulse) / `success` / `warning` / `error`; `OAStatus` exposes `color` + `systemImage` (per section 3.9: `checkmark.circle.fill`, `exclamationmark.triangle.fill`, `xmark.circle.fill`; `running` uses the dot/spinner, no glyph) so feature code can always render icon + word + color (P5).
- **Accessibility:** Dynamic Type safe — all type tokens are text styles (no point sizes anywhere); `StatusDot` diameter is `@ScaledMetric(relativeTo: .footnote)` base 6 pt; `PillLabel` text uses `OATypography.badge`/`badgeNumeric` and `.monospacedDigit()` for in-place-updating numerals; `StatusDot` requires a `label:` argument surfaced as its accessibility label; Reduce Motion freezes the pulse; Reduce Transparency is handled by the system glass API. Differentiate Without Color is satisfied structurally because `OAStatus` always supplies a glyph and callers supply the word.
- **Permissions / loading / error / empty behavior:** none — the package is pure presentation with no I/O.

**`ios/Scripts/token-lint.sh`** (executable; invoked by `ci.sh` immediately after `lint.sh`):

```bash
#!/usr/bin/env bash
# Token discipline: design primitives are allowed only inside ios/Packages/DesignSystem.
# Rules from docs/plans/ios-app/03-architecture.md section 11.4.
set -euo pipefail
ROOT="$(cd "$(dirname "${BASH_SOURCE[0]}")/../.." && pwd)"
violations="$(grep -RnE 'Color\(red:|Color\(hex|#[0-9A-Fa-f]{6}|Font\.system\(size:' \
  --include='*.swift' "${ROOT}/ios/App" "${ROOT}/ios/Packages" \
  | grep -v 'ios/Packages/DesignSystem/' \
  | grep -v 'GeneratedSources' || true)"
if [ -n "${violations}" ]; then
  echo "Token lint failed — design primitives outside ios/Packages/DesignSystem:" >&2
  echo "${violations}" >&2
  exit 1
fi
echo "✓ token lint passed"
```

## Regression risks and concerns

- **Hex tuning drifts from the plan doc:** tuned values that never land in `01-product-and-ux.md` section 3.2 make the doc lie to every later issue. Mitigation: the same-PR doc-update step is a checklist item and a Definition-of-done line.
- **Threshold gaming:** a weak implementer may lower a threshold instead of tuning a color. The contrast table in this issue is normative; thresholds changes require a design-review note in the PR and an update here — reviewers reject silent edits.
- **Snapshot flakiness across simulator runtimes:** baselines are environment-pinned (Apple Silicon, pinned Xcode 26.x, iOS 26.0 runtime). Record on a CI-matching runtime; on unexplained CI failure, inspect the `.xcresult`, never re-record (policy section 6.2/6.5).
- **Lint false positives:** `#[0-9A-Fa-f]{6}` can match a 6-hex-char issue reference (e.g. `#123456`) or a hex string in a comment. Acceptable cost — reword the comment; never widen the exclusion list beyond `DesignSystem/` and `GeneratedSources` without updating `03-architecture.md` section 11.4.
- **Glass misuse downstream:** nothing compiler-enforces "no glass-on-glass" or "content opaque". Mitigation: `GlassComposerContainer` is the only sanctioned custom-glass entry point, its doc comment states the P1 rules, and the `.glassEffect` grep recipe makes review audits one command.
- **API-shape lock-in:** `OAColor`/`OATypography` names become load-bearing for every M5+ issue. The spellings in this issue (normalized per `03-architecture.md`) are final; renames after M5-02 starts would fan out across milestones.
- **Pulse animation in snapshots:** StatusDot's repeating animation must not make snapshots non-deterministic — snapshot the static (non-animated) initial frame; the determinism checklist (section 6.4) applies.
- **CodeUI coupling:** M6's `CodeBlockView` consumes `CodeBackground`/`CodeBorder` and the radius tokens; renaming or retyping them later breaks that slice — names are frozen here.
