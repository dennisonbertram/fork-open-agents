## Why this matters

Every v1 screen that touches sessions, chats, the sandbox, files, diffs, or git speaks `OpenAgentsCore` value types — never generated `Components.Schemas.*` types. This issue creates that vocabulary (wire-named Codable structs, lenient `.unknown`-style enums, `JSONValue`, fractional-second ISO-8601 dates) and the typed facades (`SessionsAPI`, `ChatsAPI`, `SandboxAPI`, `GitAPI`) that map generated types to domain models strictly inside `ios/Packages/APIClient`. It also regenerates `ios/Packages/OpenAgentsAPI` against the spec with batches B-D landed, so the generated surface and the facades land together. Without this layer, M6 (persistence + inbox + transcripts) and M9 (ship code) have no types to build on, and any server schema change would detonate inside SwiftUI views instead of inside one fixture-tested mapping layer.

## User/operator path protected

The architecture boundary itself: generated types never leak above `APIClient`, and a server schema change breaks decoding in this layer's fixture tests — never in UI code. Concretely: an iOS contributor can change any feature package without ever importing `OpenAgentsAPI` (grep-enforced), and when `apps/web` changes a sessions/chats/sandbox/diff/git response shape, the failure shows up as a red `swift test --package-path ios/Packages/APIClient` decode test with the operationId in the error, not as a blank screen. Downstream protected paths fed by this slice: P2 (sessions inbox renders), U6/U7 (diff, commit, PR, resume) per `docs/plans/ios-app/06-testing-strategy.md` section 2.

## Behavior contract

- Given `StubURLProtocol` serves `ios/Fixtures/json/sessions-list.json` for `GET /api/sessions?status=all`, when `client.sessions.list(status: .all, limit: nil, offset: nil)` is awaited, then it returns an `OpenAgentsCore.SessionListPage` whose first `Session` carries the fixture's `id`/`title`/`repoOwner`, whose `createdAt` is a `Foundation.Date` equal to the fixture's ISO instant (fractional seconds preserved), and whose static type mentions no `Components.Schemas.*` name.
- Given a sessions fixture with `status: "archived"` filter shape containing `pagination: { limit: 50, offset: 0, hasMore: true, nextOffset: 50 }`, when `list(status: .archived, ...)` runs, then `SessionListPage.pagination` is mapped field-for-field and `archivedCount` is nil.
- Given `ios/Fixtures/json/chats-list.json` served for `GET /api/sessions/{sessionId}/chats`, when `client.chats.list(sessionId:)` runs, then it returns `ChatListPage` with `defaultModelId` and per-chat `hasUnread`/`isStreaming` mapped from the fixture.
- Given a session JSON whose `status` is `"hibernation_pending"` (a value this client has never seen), when it is decoded, then decoding succeeds, `session.status.rawValue == "hibernation_pending"`, and nothing throws — the lenient-enum rule from `docs/plans/ios-app/03-architecture.md` section 3.1.
- Given the stub responds `409` with body `{"error":"Sandbox is unavailable. Please resume sandbox."}` on `GET /api/sessions/{sessionId}/diff`, when `client.sessions.diff(sessionId:)` runs, then it throws the M3-01 `APIError.conflict(kind: .sandboxUnavailable, message:)` — never a decode error, never a raw string.
- Given `POST .../git/commit` returns 200 with `{"committed":false,"pushed":false,"error":"push rejected: remote diverged"}`, when `client.git.commit(...)` runs, then it returns a `CommitResult` whose `error` is that string and does not throw — in-200 errors are data, per `docs/plans/ios-app/02-api-contract-and-networking.md` section 4.2.
- Given `GET .../git/status` returns 200 `{"status":null}`, when `client.git.status(sessionId:)` runs, then it returns `nil` (paused-sandbox result-state), not an error.
- Given `ios/Fixtures/json/sandbox-status.json` with `lifecycle.serverTime = 1781234567890`, when `client.sandbox.status(sessionId:)` runs, then `SandboxLifecycle.serverTime` is a `Double` epoch-milliseconds value, never a `Date` (countdowns use server-time deltas; epoch-ms fields are documented numbers in the spec).
- Given the sessions-list fixture with the required `id` field deleted from one row (simulating a breaking server change), when the facade decode test runs, then `client.sessions.list(...)` throws `APIError.decoding` carrying operationId `listSessions` — the canary that proves schema breaks land in this layer's tests.
- Given the merged branch, when `grep -rn "import OpenAgentsAPI" ios/Packages ios/App | grep -v "ios/Packages/APIClient/"` runs, then it prints nothing.
- Given the regenerated client committed by this PR, when `./ios/Scripts/check-api-drift.sh` runs, then it exits 0.

## Product and design spec

Developer-facing API surface; no end-user UI. The "product" is the facade ergonomics every feature package consumes:

- Entry point: `OpenAgentsClient` (M3-01) gains/realizes four facade properties: `sessions: SessionsAPI`, `chats: ChatsAPI`, `sandbox: SandboxAPI`, `git: GitAPI`. All are `Sendable` structs constructed by `OpenAgentsClient` from the two generated `Client` instances (`apiClient`, `longRunningClient`) plus the `EventLogging` seam.
- Every method is `async throws`, throws only the M3-01 `APIError`, returns only `OpenAgentsCore` types, and is named per `docs/plans/ios-app/03-architecture.md` section 11 (camelCase, `Id` spelling: `sessionId`, `chatId`, `prNumber`).
- States: success (domain value), thrown `APIError` (taxonomy owned by M3-01), and result-state errors carried inside 200 bodies (`CommitResult.error`, `OpenPullRequestResult.error`, `GeneratePrContentResult.error`, `git/status` `nil`). Loading/empty presentation is feature-package scope, not this layer.
- Accessibility/copy/permissions: not applicable (no UI). Error copy selection by `error_kind` is owned by `docs/plans/ios-app/07-observability.md` section 12 and later feature issues.

Lenient enum pattern (copy verbatim; decoding can never throw):

```swift
public struct SessionStatus: RawRepresentable, Codable, Hashable, Sendable {
  public let rawValue: String
  public init(rawValue: String) { self.rawValue = rawValue }
  public static let running = SessionStatus(rawValue: "running")
  public static let completed = SessionStatus(rawValue: "completed")
  public static let failed = SessionStatus(rawValue: "failed")
  public static let archived = SessionStatus(rawValue: "archived")
}
```

Model rules (from `docs/plans/ios-app/03-architecture.md` section 3.1, restated as acceptance):

- Property names equal JSON wire names exactly (`sessionId`, `prNumber`, `latestChatId`) — zero `CodingKeys` enums in `OpenAgentsCore`.
- Every model: `Codable, Equatable (or Hashable), Sendable`, explicit `public init(...)` memberwise initializer (so APIClient mapping extensions can construct them), `///` doc comment on every public declaration.
- ISO timestamps are `Date`; sandbox `lifecycle` epoch-ms fields are `Double`; unknown-shaped JSON (`sandboxState`, `composioSelection`) is `JSONValue?`.
- `OpenAgentsCore` keeps zero dependencies (Foundation only); no `import OpenAgentsAPI` anywhere in it.

Mapping rules (exact):

- All mapping happens in `ios/Packages/APIClient/Sources/APIClient/Mapping/*.swift`; thrown errors funnel through the M3-01 `ErrorMapper` so every method throws `APIError` only.
- `createSession`'s returned chat row has no `hasUnread`/`isStreaming`; mapping defaults both to `false`.
- In-200 `error` fields and `git/status` `{"status":null}` map to result-state values, never thrown errors.
- Generated string fields for evolvable statuses map via `SessionStatus(rawValue:)` etc. — never `switch` exhaustively over raw strings in mapping code.

Boundaries honored: `getChat` (chat snapshot), `persistAssistantMessage`, and the chat stream/stop operations are NOT exposed on `ChatsAPI` here — the hand-rolled chat history layer over `RawHTTPClient` owns them (`02-api-contract-and-networking.md` section 0.4; built in M6-04/M7). No GRDB, no polling, no NSCache (M3-03 owns `AdaptivePoller` and the GitHub dedupe cache).

## Regression risks and concerns

- Closed generated enums: if any M1 batch declared a status field with `z.enum`, the generated Swift enum throws on unknown server values — the exact forward-compat failure the lenient rule exists to prevent. The checklist verifies `String` posture before any mapping is written; a violation is a server spec bug, never worked around in Swift.
- Wire-name drift: a renamed domain property silently breaks GRDB blob decoding later (M6 stores domain JSON). `encodingEmitsWireNames` pins the contract now.
- Facade/operation mismatch: routing a class-L operation (`commitChanges`, `resumeSandbox`) to the 30 s `apiSession` would time out real commits/resumes. The facade table is the contract; the PR review checks every `longRunningClient` row.
- In-200 errors thrown by accident would turn "push rejected" into a generic alert and break M9-04's result-state UI. `commitErrorIsResultStateNotThrown` guards it.
- `SessionDetail` is the largest hand-mirrored shape; a missed optional field fails decode on real data even when fixtures pass. Mitigation: mirror `components.schemas.Session` from the committed spec (not the research brief), and keep every nullable column optional.
- Fixture realism: hand-authored fixtures (sandbox/diff/git fallback) can encode wishful shapes. Mitigation: derive from `apps/web/tests/contract/` assertions, mark `"recorded": false` in meta, and re-record from a live sandbox in the M9 milestone when one exists routinely.
- Regenerating with batches E-F partially landed is harmless (extra generated operations are unused until M3-03), but the filter output count will differ from `included=47`; record the actual count in the PR rather than forcing it.
