## Why this matters

Onboarding is the first sixty seconds of the product and the only mandatory wall in the app. This issue turns the M4 auth machinery (Vercel OAuth coordinator, native Sign in with Apple, `AuthController` state machine) and the M5-02 shell (typed router, `DeepLink`, `RootView`) into the four user-facing onboarding surfaces from `docs/plans/ios-app/01-product-and-ux.md`: SCR-01 Welcome, SCR-02 Auth In Progress, SCR-03 Connect GitHub, and SCR-51 Sign-in Gate. It also encodes three hard product lessons: a signed-out deep link must never silently bounce (lesson B12 — the destination is preserved and restored after sign-in), the auth handoff must never show a blank screen or strand the user after process death, and the app must be usable in Chat-Only mode before GitHub is connected ("Not now" is a first-class path, which matters doubly for Apple-only sign-ins that arrive with zero connections per `docs/plans/ios-app/04-auth.md` section 8.6). Finally, it wires the DEBUG launch-environment seam from `docs/plans/ios-app/06-testing-strategy.md` section 7.1 so every later XCUITest can bypass the real OAuth dance — without this seam the M-late smoke suite cannot exist.

## User/operator path protected

U1 (`docs/plans/ios-app/00-overview.md` section catalog): a signed-out user completes Vercel OAuth sign-in (or Sign in with Apple) in under 60 seconds, lands in the signed-in shell, and sees **zero** permission prompts during onboarding (`01-product-and-ux.md` section 8: no prompt before step 5). Cross-references P1 from `docs/plans/ios-app/06-testing-strategy.md` section 2 (session survives relaunch — owned by M4-03; this issue protects the screens around it). Secondary protected path: lesson B12 — a signed-out deep link to a session, chat, or background run always shows SCR-51 with the destination preserved and restored after sign-in.

## Behavior contract

- Given a fresh install with no Keychain token, when the app launches, then `RootView` shows SCR-01 Welcome: app glyph, title "Open Agents", tagline "Your coding agents, anywhere.", a system `SignInWithAppleButton`, a "Continue with Vercel" button, and a "Privacy Policy" · "Terms of Service" footer — and no permission prompt of any kind appears.
- Given SCR-01, when the user taps "Continue with Vercel" (or the Apple button), then the screen transitions to SCR-02 ("Signing you in…" with the app glyph and a labeled spinner — never a blank view) while `ASWebAuthenticationSession` / `ASAuthorizationController` runs via the M4 coordinators.
- Given the user cancels the auth sheet (`ASWebAuthenticationSessionError.canceledLogin` or `ASAuthorizationError.canceled`), when control returns to the app, then SCR-01 is shown again with **no** error footnote (silent cancel per `04-auth.md` sections 4 and 8.6).
- Given the token exchange fails (server error, `?error=` callback, non-200 verify), when control returns, then SCR-01 shows the inline footnote "Sign-in didn't finish. Try again." and both buttons are enabled.
- Given the app process is killed while SCR-02 is showing (mid-flow), when the app relaunches, then the `AuthController` bootstrap finds no token and the app lands cleanly on SCR-01 — never a stuck progress state (the in-progress phase is in-memory only, never persisted).
- Given the device is offline (`ConnectivityMonitor` unsatisfied), when SCR-01 renders, then both sign-in buttons are disabled and the footnote reads "You're offline. Connect to sign in."; when connectivity returns, the buttons re-enable without relaunch.
- Given sign-in succeeds and the bootstrap `GET /api/auth/info` reports `hasGitHubInstallations == true`, when `AuthController` enters `.signedIn`, then the app goes straight to the four-tab shell (SCR-03 is skipped).
- Given sign-in succeeds and `hasGitHubInstallations != true` and no per-user skip flag is set, when `.signedIn` is entered, then SCR-03 Connect GitHub appears with a skeleton over the body while `GET /api/github/connection-status` loads, then renders the state for the response (`not_connected` / `reconnect_required` / `connected` without installations → CTA states; `connected` with `hasInstallations == true` → advance to the shell).
- Given SCR-03, when the user taps "Connect GitHub", then the app mints a fresh OTT via authenticated `GET /api/auth/one-time-token/generate`, opens `{baseURL}/api/native-auth/bridge?ott=<ott>&next=<flow path>` in `ASWebAuthenticationSession` (next = `/get-started?step=github` when `not_connected`, `/api/github/app/install?reconnect=1` when `reconnect_required`, `/api/github/app/install` when connected without installations), and when the user dismisses the sheet, re-fetches `GET /api/github/connection-status`: `connected` + `hasInstallations == true` advances to the shell.
- Given a bridge hop completed in this app session and the re-fetch returns `connected` with `hasInstallations == false`, when SCR-03 re-renders, then the CTA is replaced by the static admin-pending row — "Waiting for an admin to approve access to {org}." when exactly one pending org is resolvable via `GET /api/github/orgs/install-status`, else "Waiting for an admin to approve access." — plus a "Check Again" button that re-fetches connection status.
- Given SCR-03, when the user taps "Not now", then the per-user skip flag is persisted, the app enters the four-tab shell (Chat-Only usable), and subsequent launches go straight to the shell; the connection-status fetch failing shows the standard inline error card ("Couldn't load GitHub status." + "Retry") and never blocks "Not now".
- Given the app is signed out and receives `openagents://sessions/{sessionId}/chats/{chatId}` (or any gated `DeepLink`), when the URL is handled, then SCR-51 appears full-screen with title "Sign in to view this", body "This session belongs to an Open Agents account." (link type "session"/"run"/"page" per `DeepLink` case), and a "Sign In" button; after successful sign-in the preserved destination is opened exactly once via `AppRouter.open(_:)` — the Connect GitHub interstitial is skipped when a pending deep link exists (the destination wins). Cancelling sign-in keeps SCR-51 on screen; the destination is never silently dropped.
- Given a DEBUG build launched with `OPENAGENTS_UITEST=1`, `OPENAGENTS_API_BASE_URL=<mock>`, and `OPENAGENTS_TEST_BEARER_TOKEN=<token>`, when the app starts, then the in-memory token store is seeded, animations are disabled, and the app boots signed-in without any browser session; with the token variable absent it boots to SCR-01. In Release builds these variables are ignored (compiled out via `#if DEBUG`).

## Product and design spec

Exact copy, layout, and states are normative in `docs/plans/ios-app/01-product-and-ux.md` — SCR-01/02/03 (section 4, Onboarding group), SCR-51, and section 8 flow. Summary of what this issue must reproduce verbatim:

- **SCR-01 Welcome**: centered 88 pt app glyph, title "Open Agents" (`Type.screenTitle`), tagline "Your coding agents, anywhere.", stacked buttons — system `SignInWithAppleButton(.signIn)` (`.black`/`.white` per mode, equal prominence per guideline 4.8) then "Continue with Vercel" (`.glassProminent`). Footer links "Privacy Policy" · "Terms of Service" (open in `SFSafariViewController`). Opaque `systemBackground` (onboarding is opaque per the section 3.5 glass map). Error footnote: "Sign-in didn't finish. Try again." Offline footnote: "You're offline. Connect to sign in." No carousel, no feature tour, no skippable pages.
- **SCR-02 Auth In Progress**: app glyph + small labeled spinner, copy "Signing you in…", `accessibilityLabel("Signing you in")`. Failure state: "Something went wrong signing you in." + "Try Again" button returning to SCR-01.
- **SCR-03 Connect GitHub**: glyph `folder.badge.gearshape`, title "Connect GitHub", body "Agents need repository access to read code and open pull requests. You choose which repositories.", primary "Connect GitHub", secondary "Not now". Loading: `redacted(reason: .placeholder)` skeleton over the body. Error: inline error card per section 4.0 (`exclamationmark.triangle.fill` in `StatusError` + message + "Retry"). Admin-pending: static row "Waiting for an admin to approve access to {org}." (fallback without `{org}` when unresolvable) + "Check Again".
- **SCR-51 Sign-in Gate**: title "Sign in to view this", body "This {link type} belongs to an Open Agents account." with link type "session" (`.session`, `.chat`), "run" (`.backgroundRun`), "page" (fallback), button "Sign In" presenting the same sign-in surface as SCR-01.
- All tokens by name only from the M5-01 DesignSystem package (`OASpacing`, `Type.*`, `Color.oa*`); 44×44 pt hit targets; Dynamic Type to AX5 (buttons stack vertically already; verify no fixed heights); status always glyph + word + color (P5). No haptics anywhere in onboarding (not in the section 3.7 map). Permissions: none requested — zero permission prompts before the first send (section 8).

## Regression risks and concerns

- **B12 double-restore or lost destination**: restoring the pending deep link on every `.signedIn` observation would re-navigate on token rotation; restoring before `RootView` mounts the tabs would drop it. The consume-exactly-once test (SignInGateTests) is the tripwire; restoration must run after the shell exists.
- **`request_sent` inference is heuristic by design**: the server's connection-status union has no `request_sent` value and the app cannot read the in-sheet terminal URL without universal links. Mapping post-hop `connected`+no-installs to the pending row also catches "user closed GitHub without installing" — acceptable (the row offers "Check Again" and the CTA path remains reachable via re-entry), but do not "fix" this by parsing sheet URLs or adding server redirects in this slice; that is the documented v2 hardening.
- **OnboardingFeature dependency creep**: importing `APIClient` or `PersistenceKit` here violates the `03-architecture.md` section 3.10 posture and recreates the cycle the protocol seams exist to prevent. Review gate: `grep -rn "import APIClient\|import PersistenceKit" ios/Packages/OnboardingFeature/Sources` returns nothing.
- **Seam leaking into Release**: the launch-environment overrides must be `#if DEBUG`-compiled out, not runtime-gated — a Release binary honoring `OPENAGENTS_TEST_BEARER_TOKEN` is an auth bypass. Reviewer checks the `#if DEBUG` fences; the App Store archive in `08-ci-cd-release.md` builds Release.
- **OTT exposure**: a logged bridge URL leaks a live (3-minute, single-use) credential. The recording-logger redaction test plus the section 11.7 grep are the guards.
- **Skip-flag scoping**: a global (non-per-user) skip flag would hide SCR-03 from a second account on the same device; the key embeds the user id.
- **Apple-only users**: they arrive with `hasGitHub == false` and no Vercel connection; SCR-03 must render for them and "Not now" must still produce a usable Chat-Only shell — covered by the store tests' `not_connected` path.
- **Snapshot flakiness**: glass/system chrome renders are layout-only in snapshots (`06-testing-strategy.md` section 6.4); keep onboarding surfaces opaque (they are, per the section 3.5 map) and inject fixed dates/locale.
