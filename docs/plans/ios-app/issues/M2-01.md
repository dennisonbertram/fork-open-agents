## Why this matters

This is the first Swift code in the monorepo. Every later iOS slice (generated OpenAPI client, CI gate, auth, streaming, screens) assumes this exact tree exists: `ios/App` as a thin XcodeGen-generated shell and 16 local SPM packages under `ios/Packages/*` with the layering rules, isolation posture, and exact dependency pins from `docs/plans/ios-app/03-architecture.md`. Getting the package graph and `Package.swift` templates right now is what makes "only `APIClient` imports `OpenAgentsAPI`", "features never import features", and Swift 6.2 strict concurrency enforceable by the compiler for the rest of the epic. It also proves the contributor bootstrap path: clone, run one script, build.

## User/operator path protected

A contributor (human or agent) clones the repo on a machine with Xcode 26.x, runs `ios/Scripts/generate-project.sh`, opens `ios/App/OpenAgents.xcodeproj`, and builds the empty app for the `iPhone 17 Pro` and `iPad Pro 13-inch (M4)` simulators with zero warnings — and every package under `ios/Packages/*` compiles. No generated artifact is ever committed, and the existing web gate (`bun --bun run ci`) stays green with `ios/` present.

## Behavior contract

- Given a fresh checkout with Xcode 26.x and XcodeGen ≥ 2.45.4 installed, When the contributor runs `ios/Scripts/generate-project.sh`, Then `ios/App/OpenAgents.xcodeproj` is written, `git check-ignore ios/App/OpenAgents.xcodeproj` exits 0, and `git status --porcelain` shows no generated artifacts.
- Given the generated project, When the contributor runs `xcodebuild -project ios/App/OpenAgents.xcodeproj -scheme OpenAgents -destination 'platform=iOS Simulator,name=iPhone 17 Pro' build` and the same for `name=iPad Pro 13-inch (M4)`, Then both builds succeed with zero `warning:` lines in the build log.
- Given the 16 packages, When `swift build --package-path ios/Packages/<Name>` runs for each of the six nonisolated-default packages (`OpenAgentsCore`, `OpenAgentsAPI`, `APIClient`, `StreamEngine`, `PersistenceKit`, `Observability`), Then each builds on the macOS host; the ten iOS-only packages compile transitively in the app build above (AppShell depends on all of them).
- Given the built app launched on a simulator, When it boots, Then `Diagnostics.bootstrap()` runs in `OpenAgentsApp.init()`, the placeholder `RootView` renders, and the Info.plist registers `CFBundleURLTypes` with scheme `openagents` and the `OpenAgentsBaseURL` key.
- Given the `Observability` package, When `RequestID.generate()` is called, Then it returns `ios.<lowercase-uuidv4>` (40 chars, matches the server-safe pattern `/^[A-Za-z0-9._:/=-]{8,128}$/` from `apps/web/lib/harness/request-id.ts`), and repeated calls return distinct values.
- Given XcodeGen is not installed (error case), When `ios/Scripts/generate-project.sh` runs, Then it exits non-zero with the shell's command-not-found error; the fix (`brew install xcodegen`) is documented in this issue and in the script's sibling docs.
- Given an unknown URL is opened against the app (edge case), When `AppEnvironment.handle(url:)` receives it, Then the placeholder implementation logs it via `Log.ui` and does nothing else (no crash, no navigation — full deep-link parsing is M5 scope).
- Given the `ios/` tree exists, When `bun --bun run ci` runs at the repo root, Then it passes unchanged (web tooling does not lint or test `ios/**`).

## Product and design spec

No user-facing product surface ships in this slice. Entry point: Xcode (or `xcodebuild`) running the `OpenAgents` scheme on a simulator. Primary flow: app boots → `RootView` shows a static placeholder (e.g. the text `Open Agents` centered; exact styling is irrelevant and is replaced by M5 AppShell work). States: only this single placeholder state; no loading/empty/error UI exists yet, and none should be invented. Copy: `CFBundleDisplayName` is `Open Agents`. Accessibility: nothing beyond the default; no `accessibilityIdentifier`s are required yet (those arrive with `A11yID` consumers). Permissions: none are prompted — the `NSMicrophoneUsageDescription` Info.plist key is present (declared in `project.yml` per `03-architecture.md` §6.1) but no code touches the microphone; the first prompt must not appear until the M8 voice slice.

## Regression risks and concerns

- Web gate breakage: new `ios/**` files could trip ultracite/oxlint/oxfmt or future TS globs. Mitigation: run `bun --bun run ci` in this PR; minimal `ignorePatterns` entry if needed; formal two-direction test owned by the M2 CI sibling.
- Accidental commit of generated artifacts: a committed `.xcodeproj` poisons every future XcodeGen run. Mitigation: `ios/.gitignore` + the explicit `git check-ignore` and `git status --porcelain` checklist steps.
- Template/posture mistakes are deferred time bombs: a MainActor-default manifest on an infrastructure package (or a missing `.enableUpcomingFeature` line) surfaces as strict-concurrency build breaks in M3+. Mitigation: the manifest table here is normative; copy templates verbatim; review diff against §4.
- Pin drift: external pins duplicated across manifests must stay identical. Mitigation: single-pin policy from §2.3; `grep -r "swift-snapshot-testing" ios/Packages/*/Package.swift` in review; record any 1.18.x deviation in the pin table.
- Dependency-graph violations sneaking in later: nothing enforces "only APIClient imports OpenAgentsAPI" yet beyond SPM manifests. The grep-lint table (§11.4) is wired into CI by the M2 CI sibling; until then review manually.
- Placeholder permanence: `AppShell`'s `AppEnvironment`/`RootView` stubs must be visibly marked `/// Placeholder` so the M5 composition-root slice replaces rather than extends them.
- Simulator-name drift: `iPhone 17 Pro` / `iPad Pro 13-inch (M4)` names on the CI runner image may differ from local; this issue pins local verification, and the M2 CI sibling corrects runner-side names in `ios/Scripts/env.sh`.
