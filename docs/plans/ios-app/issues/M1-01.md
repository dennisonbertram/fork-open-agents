## Why this matters

The iOS app's generated Swift client (`swift-openapi-generator` 1.12.2, built in milestone M2) consumes `apps/web/openapi.json` verbatim. The committed spec today (6 paths / 10 operations) has five properties that make Swift codegen unusable or dangerous:

1. **49 occurrences of `"additionalProperties": false`** — swift-openapi-generator maps closed objects to closed Swift structs that fail to decode when the server adds any new response field. Every additive backend change would crash shipped iOS builds.
2. **No `components.schemas`** — every schema is inlined, so the generator emits anonymous nested types like `Operations.listSkills.Output.Ok.Body.jsonPayload` for every shape. The `{ "error": string }` envelope alone is repeated ~30 times.
3. **No `format: date-time`** on ISO timestamp strings — Swift gets `String` instead of `Foundation.Date`.
4. **Three untyped mutation responses** — `commitChanges`, `openPullRequest`, and `mergePullRequest` document their 200 bodies as `z.record(z.string(), z.unknown())`, which becomes an untyped dictionary in Swift for the three highest-stakes write operations in the app.
5. **No `securitySchemes`** — the generated client and its auth middleware have no spec-level statement that operations are authenticated.

Batches B–F (M1-02 through M1-06) add ~100 operations on top of the helpers this issue introduces. Landing the hygiene first means every later batch inherits open objects, `$ref` hoisting, and security declarations by construction instead of retrofitting them.

## User/operator path protected

- **Existing spec consumers keep working unchanged.** The typed web client `apps/web/lib/api/client.ts` (built on `openapi-fetch` + `apps/web/lib/api/openapi-types.ts`) must still typecheck and its unit test must still pass. No API route behavior changes at all — this issue only rewrites how the contract document is built and regenerates the two committed artifacts.
- **Both drift gates keep working unchanged.** `apps/web/scripts/check-openapi.ts` (string compare, run via `bun run --cwd apps/web openapi:check`) and the no-drift test in `apps/web/lib/api/openapi-spec.test.ts` (deep compare, runs inside `bun run ci`) must both exit green at the end of the PR.
- **Future protected path:** an iOS build in the field keeps decoding responses after the server ships an additive field (open objects), and the Swift API surface uses stable names under `Components.Schemas.*`.

## Behavior contract

- **Given** the implemented builder, **when** `bun run --cwd apps/web openapi:generate` runs, **then** `apps/web/openapi.json` contains zero occurrences of `"additionalProperties": false`, a `components.securitySchemes` object with `bearerAuth` and `cookieAuth`, a document-level `security: [{ bearerAuth: [] }, { cookieAuth: [] }]`, and a `components.schemas` map whose keys are sorted alphabetically.
- **Given** the regenerated artifacts are committed, **when** `bun run --cwd apps/web openapi:check` runs, **then** it exits 0 and prints `✓ openapi.json is in sync with openapi-spec.ts`.
- **Given** the regenerated artifacts are committed, **when** `bun test apps/web/lib/api/openapi-spec.test.ts` runs, **then** all tests pass, including the existing no-drift deep-equal test and the new hygiene tests.
- **Given** a schema built from `z.record(z.string(), z.someType())` (where `additionalProperties` is a schema object, not `false`), **when** the stripping pass runs, **then** the schema-object `additionalProperties` is preserved — only the literal `false` value is removed.
- **Given** two different schema shapes registered under the same component name, **when** `buildOpenApiDocument()` runs, **then** it throws `Error("OpenAPI schema name collision: <name>")` — surfacing in `openapi:generate`, `openapi:check`, and the unit test rather than silently emitting a wrong `$ref`.
- **Given** the same builder called twice in one process, **when** the two documents are deep-compared, **then** they are identical (the registry is per-build, not module-global).
- **Given** an operation whose `operationId` is in the test's `publicOperationIds` allowlist, **when** the "every operation documents a 401" test runs, **then** that operation is exempt; every operation not in the allowlist still must document a 401. (No public operations exist in the spec after this batch; the allowlist is pre-seeded with `"listModels"` and `"getSharedChatStatus"` for batches E and F per `docs/plans/ios-app/02-api-contract-and-networking.md` section 2.4.)
- **Given** the `userSkillSchema` response shape, **when** the spec is built, **then** `createdAt` and `updatedAt` carry `"format": "date-time"` (via `z.iso.datetime()`).
- **Given** the `commitChanges`, `openPullRequest`, and `mergePullRequest` operations, **when** the spec is built, **then** their 200 response schemas are `$ref`s to `CommitResult`, `OpenPullRequestResult`, and `MergePullRequestResult` whose properties mirror the real server return shapes (see Integration spec) — no `z.record(z.string(), z.unknown())` remains anywhere in `apps/web/lib/api/openapi-spec.ts`.
- **Given** a running local server, **when** the existing contract tests run (`CONTRACT_BASE_URL=http://localhost:3000 bun run test:contract`), **then** `apps/web/tests/contract/skills-crud.test.ts` and `apps/web/tests/contract/git-routes.test.ts` still pass — proof that no route behavior changed.
- **Edge:** **given** a deleted or stale `apps/web/openapi.json`, **when** `openapi:check` runs, **then** it still exits 1 with the existing remediation message (this existing behavior must not regress).

## Product and design spec

This slice has no end-user UI. The "product" is the developer-facing contract surface:

- **Entry point:** `buildOpenApiDocument()` in `apps/web/lib/api/openapi-spec.ts`, invoked by `apps/web/scripts/generate-openapi.ts`, `apps/web/scripts/check-openapi.ts`, and `apps/web/lib/api/openapi-spec.test.ts`.
- **Primary flow:** edit builder → regenerate both artifacts → gates verify byte-for-byte sync.
- **States:** in-sync (gates green) vs drifted (gates exit 1 with the exact remediation command) vs collision (build throws with the colliding name).
- **Copy:** keep the existing checker messages verbatim; the only new message is `OpenAPI schema name collision: <name>`.
- **Accessibility / permissions / loading / empty states:** not applicable — build-time tooling only; no auth changes, no UI.

**Blocker 1 — stripping helper.** Add `stripClosedObjects(node: unknown): unknown` exactly per `docs/plans/ios-app/02-api-contract-and-networking.md` section 2.2 Blocker 1: recursive walk; drop the key only when `key === "additionalProperties" && value === false`; recurse into arrays and objects; wrap the existing `j(schema, io)` helper so every Zod→JSON-schema conversion passes through it. Export `stripClosedObjects` as a named export so the unit test can exercise the schema-object-preservation case directly.

**Blocker 2 — schema registry.** Add `makeRef(registry: SchemaRegistry)` per section 2.2 Blocker 2 (registry type `Map<string, JsonSchema>`; identical re-registration is a no-op; different shape under the same name throws `OpenAPI schema name collision: <name>`; returns `{ $ref: "#/components/schemas/<name>" }`). Export `makeRef` as a named export for the collision unit test. Instantiate the registry inside `buildOpenApiDocument()` (per-build, not module scope) and emit `components.schemas` from `[...registry.entries()].sort(([a], [b]) => a.localeCompare(b))`. Because `$ref`s cannot live inside Zod schemas, add a raw-JSON response helper alongside the existing Zod one:

```ts
const rawJsonResponse = (description: string, schema: JsonSchema) => ({
  description,
  content: { "application/json": { schema } },
});
```

and change `errorResponse(description)` to return `rawJsonResponse(description, ref("ErrorResponse", errorSchema))`. Wrapper objects that embed refs (for example `{ skills: UserSkill[] }`) are written as raw JSON schema: `{ type: "object", properties: { skills: { type: "array", items: ref("UserSkill", userSkillSchema) } }, required: ["skills"] }`.

**Component names registered in this batch** (these become Swift type names under `Components.Schemas.*`; renaming later requires a migration note per section 2.2):

| Name | Source |
|---|---|
| `ErrorResponse` | `errorSchema` (`{ error: string }`) |
| `UserSkill` | `userSkillSchema` |
| `SessionGitStatus` | `gitStatusSchema` — register the nullable schema as-is; OpenAPI 3.0 `nullable: true` lives inside the component, so the use site stays a plain `$ref` |
| `PrStatusResponse` | the `checkPullRequest` 200 body (`{ branch, prNumber, prStatus }` nullables) |
| `CommitResult` | new schema, Blocker 4 |
| `OpenPullRequestResult` | new schema, Blocker 4 |
| `MergePullRequestResult` | new schema, Blocker 4 |

Request bodies may stay inline in this batch; hoisting them is optional and must use the section 2.2 naming table if done.

**Blocker 3 — timestamps.** In `userSkillSchema`, change `createdAt: z.string()` and `updatedAt: z.string()` to `z.iso.datetime()` (Zod 4.3.6, serialized by `z.toJSONSchema(..., { target: "openapi-3.0" })` to `{ "type": "string", "format": "date-time" }`). These are the only ISO timestamps in today's spec. The standing rule for batches B–F is established here: ISO timestamps in responses use `z.iso.datetime()`; epoch-millisecond lifecycle numbers (sandbox `serverTime`, `sandboxExpiresAt`, `hibernateAfter`, `lifecycle.lastActivityAt`) stay `z.number()` with the unit stated in the field `description`.

**Blocker 4 — typed mutation results.** Replace the three `z.record(z.string(), z.unknown())` response schemas with Zod schemas mirroring the real server return types:

- `CommitResult` mirrors `export interface CommitResult` in `apps/web/lib/github/actions/commit.ts` (line 89): `{ committed: z.boolean(), pushed: z.boolean(), branchName: z.string().optional(), commitMessage: z.string().optional(), commitSha: z.string().optional(), error: z.string().optional() }`.
- `OpenPullRequestResult` mirrors the inline return type of `openPullRequest` in `apps/web/lib/github/actions/pr.ts` (line 243): `{ success: z.boolean(), prUrl: z.string().optional(), prNumber: z.number().optional(), prStatus: z.string().optional(), requiresManualCreation: z.boolean().optional(), autoMergeEnabled: z.boolean().optional(), autoMergeError: z.string().optional(), error: z.string().optional() }`.
- `MergePullRequestResult` mirrors `export type MergePullRequestResult` in `apps/web/lib/github/actions/pr.ts` (line 30): `{ merged: z.boolean(), prNumber: z.number(), mergeCommitSha: z.string().nullable(), branchDeleted: z.boolean(), branchDeleteError: z.string().nullable() }`.

Note in the schema comments that `CommitResult` and `OpenPullRequestResult` can return `error` inside a 200 body — clients must check it (see `docs/plans/ios-app/02-api-contract-and-networking.md` section 1.8).

**Blocker 5 — security.** Add to the returned document, exactly per section 2.2 Blocker 2's sketch:

```ts
security: [{ bearerAuth: [] }, { cookieAuth: [] }],
components: {
  securitySchemes: {
    bearerAuth: { type: "http", scheme: "bearer" },
    cookieAuth: { type: "apiKey", in: "cookie", name: "better-auth.session_token" },
  },
  schemas: /* sorted registry entries */,
},
```

This is a spec-level statement only; enforcement stays server-side and the bearer transport itself is M0-01's scope.

**Compatibility:** regenerating `apps/web/lib/api/openapi-types.ts` changes the `paths` type consumed by `apps/web/lib/api/client.ts`. The only current consumers are `client.ts` itself and the typed-client test inside `openapi-spec.test.ts`; `turbo typecheck --filter=web` must stay green.

## Regression risks and concerns

- **Regenerated `openapi-types.ts` changes the `paths` type** used by `apps/web/lib/api/client.ts`. `$ref`-hoisted schemas become named types in `components["schemas"]`; the typed-client test (`api.GET("/api/settings/skills")`) and `turbo typecheck --filter=web` catch breakage.
- **Over-stripping:** removing `additionalProperties` when it is a schema object would silently untype every `z.record(...)` map in later batches. Test 2 pins the correct behavior now.
- **Module-global registry leakage:** a module-scoped registry would make repeated builds (checker + test in one process) non-deterministic or falsely collide. Test 5's build-twice assertion pins per-build instantiation.
- **Wholesale `openapi.json` diff:** adding `components` + `security` rewrites the artifact. Reviewers must review `openapi-spec.ts` and the test, and treat both artifacts as generated output verified by the gates — never hand-tuned.
- **Component renames are breaking for Swift:** once `Components.Schemas.CommitResult` ships in the generated client (M2), renaming requires a migration note. The naming table in `docs/plans/ios-app/02-api-contract-and-networking.md` section 2.2 is the contract; later batches must reuse it.
