## Why this matters

M4-01 and M4-02 produce a bearer token in the Keychain, but nothing yet decides what the app *is* — signed in, signed out, or undetermined — across launch, relaunch, token death, server-side revocation, and sign-out. This issue ships the single owner of that decision: the `@Observable` `AuthController` state machine in `ios/Packages/AuthKit`. Every screen built after this slice (onboarding in M5-03, the sessions inbox in M6-02, chat in M7) branches on `AuthController.state` and nothing else. Getting the bootstrap rules wrong produces the two worst auth bugs a mobile app can ship: signing users out on airplane mode, and a 401 loop that strands users on a dead screen. This slice also unblocks every later milestone's local development loop by adding the DEBUG-only test-auth path against `bun run web`, so no contributor needs a live Vercel OAuth dance to work on iOS features.

## User/operator path protected

P1 (`docs/plans/ios-app/06-testing-strategy.md` §2): a signed-in user kills the app, relaunches, and is still signed in; a server-side session revocation produces the re-auth state exactly once (never a stuck state, never a loop); temporary network failure at launch never signs the user out. Operator path: a contributor runs `bun run web` locally and signs the simulator app in with the static test-auth cookie, with zero OAuth setup.

## Behavior contract

- Given a fresh install (Keychain empty, dev test-auth off), When `bootstrap()` runs at launch, Then state transitions `.unknown` → `.signedOut(reason: nil)` and no network probe is issued.
- Given a Keychain token and a reachable server where `GET /api/auth/info` returns `user != nil`, When `bootstrap()` runs, Then state becomes `.signedIn(SessionUserInfo)` and the Keychain item is untouched (P1 relaunch survival).
- Given a Keychain token and `GET /api/auth/info` returns HTTP 200 with `user == nil` (session expired or revoked — the route always answers 200, `apps/web/app/api/auth/info/route.ts`), When `bootstrap()` runs, Then the Keychain is cleared and state becomes `.signedOut(reason: .sessionExpired)`.
- Given a Keychain token and the probe throws a transport error (e.g. `URLError(.notConnectedToInternet)`), When `bootstrap()` runs, Then state stays `.unknown`, the Keychain is NOT cleared, and a retry is scheduled (delays 1 s, 2 s, 4 s, 8 s, then every 30 s while still `.unknown`). The user is never signed out by airplane mode.
- Given state `.signedIn`, When `handleUnauthorized()` fires (wired to the API client's 401 signal), Then exactly one confirmation probe (`GET /api/auth/info`) runs before any sign-out: if it returns `user == nil`, the Keychain is cleared and state becomes `.signedOut(reason: .sessionExpired)` exactly once; the GRDB-nuke hook is NOT invoked (local cache is preserved for re-auth per `docs/plans/ios-app/04-auth.md` §8.7).
- Given ten concurrent `handleUnauthorized()` calls (parallel requests all 401ing), When they race, Then exactly one probe request is issued and exactly one state transition occurs (coalescing; "re-auth exactly once").
- Given state `.signedIn` and `handleUnauthorized()` whose probe returns `user != nil` (a route-level 401 quirk), When the probe completes, Then state stays `.signedIn`, the Keychain is untouched, and the once-gate re-arms so a later genuine revocation still triggers.
- Given state `.signedIn` and `handleUnauthorized()` whose probe itself throws (offline), When the probe completes, Then state stays `.signedIn` (inconclusive — never sign out without confirmation) and the gate re-arms.
- Given state `.signedOut` or `.unknown`, When `handleUnauthorized()` fires, Then it is a no-op (no probe, no transition — prevents loops).
- Given state `.signedIn`, When the user signs out, Then `POST /api/native-auth/sign-out` is called with `Authorization: Bearer` (one retry on network failure, then ignored — sign-out always succeeds locally), the Keychain is cleared, the `onSignedOut` hook is awaited exactly once (GRDB-nuke seam), and state becomes `.signedOut(reason: .userInitiated)`.
- Given a sign-in flow started (`signInWithVercel()` / `signInWithApple()` delegating to the M4-01/M4-02 coordinators), When it begins, Then state is `.signingIn`; on success the controller fetches `/api/auth/info` and lands `.signedIn(info)`; on user cancel it returns to `.signedOut(reason: nil)` silently (no thrown error); on any other failure it returns to `.signedOut(reason: nil)` and rethrows for the UI. Re-entrant sign-in calls while `.signingIn` are ignored.
- Given a DEBUG build launched with `OPENAGENTS_LOCAL_TEST_AUTH=1` and `OPENAGENTS_BASE_URL_OVERRIDE=http://localhost:3000` against `bun run web`, When `signInWithLocalTestUser()` runs, Then all AuthKit and APIClient requests carry `Cookie: open_agents_test_user_id=dev-managed-runtime-user` instead of `Authorization: Bearer`, `/api/auth/info` returns the demo user, and state becomes `.signedIn`. In a Release build none of this code exists (`#if DEBUG`, compiled out — not hidden).
- Given any log level, When any of these flows run, Then no token, `Authorization` value, `set-auth-token` value, or cookie value is ever interpolated into a log (`docs/plans/ios-app/04-auth.md` §11).

New files in `ios/Packages/AuthKit/Sources/AuthKit/`:

- `AuthState.swift` — the pinned vocabulary:

```swift
public enum AuthState: Equatable, Sendable {
  case unknown                       // launch; Keychain not yet read or probe unresolved
  case signedOut(reason: SignOutReason?)
  case signingIn
  case signedIn(SessionUserInfo)
}

public enum SignOutReason: String, Equatable, Sendable {
  case userInitiated = "user"        // raw values match 07-observability auth_signout.reason
  case sessionExpired = "server_401"
  case accountDeleted = "account_deleted"  // case reserved for M10-05; never produced here
}
```

- `AuthController.swift` — `@MainActor @Observable public final class AuthController`. Public surface: `public private(set) var state: AuthState` (initial `.unknown`), `public var onSignedOut: (@Sendable () async -> Void)?`, `public convenience init(tokenStore: KeychainTokenStore, baseURL: URL)` (the `docs/plans/ios-app/03-architecture.md` §3.4 shape), `public func bootstrap() async`, `public func signInWithVercel() async throws`, `public func signInWithApple() async throws`, `public func handleAuthCallback(_ url: URL) -> Bool` (delegates to the M4-01 coordinator's parser; returns false when M4-02 is the only consumer left), `public func handleUnauthorized() async`, `public func signOut() async`, and `#if DEBUG public func signInWithLocalTestUser() async #endif`. A designated `internal init` takes the seams for tests: `tokenStore: any AuthTokenStore`, `info: any AuthInfoFetching`, `signOutClient: any NativeSignOutPerforming`, `vercelFlow:`/`appleFlow:` closures, and `retryDelays: [Duration]` (default `[.seconds(1), .seconds(2), .seconds(4), .seconds(8)]` then `.seconds(30)` repeating). `onSignedOut` is awaited only for `.userInitiated` (and later `.accountDeleted`) — never for `.sessionExpired` (`03-architecture.md` §9.1: nuke triggers are sign-out and account mismatch, not re-auth).
- `SessionUserInfo.swift` — hand-written `Codable, Equatable, Sendable` mirror of `apps/web/lib/session/types.ts` exactly as specified in `docs/plans/ios-app/04-auth.md` §8.4 (`user: User?`, `authProvider: String?`, `isAdmin: Bool?`, `hasGitHub: Bool?`, `hasGitHubAccount: Bool?`, `hasGitHubInstallations: Bool?`; nested `User` = `id`, `username`, `email: String?`, `avatar: String`, `name: String?`). Decoding is lenient: unknown keys ignored, all flags optional. Stays hand-written: AuthKit deliberately does not depend on the generated client (`03-architecture.md` §3.4); do not branch on `authProvider` (hardcoded `"vercel"` server-side today).
- `AuthInfoClient.swift` — `public protocol AuthInfoFetching: Sendable { func fetchAuthInfo() async throws -> SessionUserInfo }` plus the URLSession conformance: `GET {baseURL}/api/auth/info` on an ephemeral, cookie-disabled session (`httpCookieStorage = nil`, `httpShouldSetCookies = false`, `httpCookieAcceptPolicy = .never` — `04-auth.md` §8.2), header `Authorization: Bearer <token>` from the token store, `x-request-id: ios.<uuid>` via `RequestID.generate()` from the `Observability` package. HTTP 200 decodes `SessionUserInfo` (a body with `user` absent decodes to `user == nil`); HTTP 401 is treated identically to `user == nil` (dead token); transport errors throw.
- `NativeSignOutClient.swift` — `public protocol NativeSignOutPerforming: Sendable { func signOut() async throws }` plus the conformance: `POST {baseURL}/api/native-auth/sign-out` (route from M0-03, `apps/web/app/api/native-auth/sign-out/route.ts`) with `Authorization: Bearer`, `Origin: openagents://` (the §8.2 belt-and-braces rule for `/api/native-auth/*` POSTs), empty body; reuse M4-01's raw request helper in AuthKit if one exists (discovery step in the checklist) instead of duplicating it.

- `ios/Packages/AuthKit/Tests/AuthKitTests/AuthControllerStateTests.swift` — `@Suite("AuthControllerState")`, stub `AuthTokenStore` / `AuthInfoFetching` / `NativeSignOutPerforming` recording fakes, short injected `retryDelays`:

  - `concurrentUnauthorizedCallsCoalesce` — 10 parallel `handleUnauthorized()` → probe call count 1, one transition.
  - `unauthorizedWithValidProbeStaysSignedInAndRearms` — probe returns user → still `.signedIn`; a second `handleUnauthorized()` with `user == nil` then signs out (gate re-armed).
  - `unauthorizedWhileSignedOutIsNoOp` — probe call count 0.

## Regression risks and concerns

- **Spurious sign-out is the catastrophic failure.** Any path that clears the Keychain without a confirmed `user == nil` (network error treated as 401, probe-throw treated as revocation) destroys P1. The state table in the Behavior contract is exhaustive; review every `tokens.clear()` call site against it.
- **401 loops / stuck states:** `handleUnauthorized()` re-entering while signed out, or the gate never re-arming after `still_valid`, produces either an infinite probe loop or a dead gate. The coalescing and re-arm tests are the tripwires.
- **`onSignedOut` over-firing:** invoking the nuke hook on `.sessionExpired` would silently delete a user's offline cache on every server-side session expiry — explicitly tested (`unauthorizedProbeConfirmsRevocationExactlyOnce` asserts the hook is NOT called).
- **Test-auth leaking into Release:** the cookie branch must be `#if DEBUG` (compiled out), not runtime-gated; reviewer greps `grep -rn "open_agents_test_user_id" ios/Packages | grep -v "#if DEBUG" -A0` and confirms the Release plist lacks `NSAppTransportSecurity`.
- **Drift between `Info.plist` and `Info-Debug.plist`:** mitigated by deriving the Debug plist in `generate-project.sh` (never hand-edited, gitignored); if XcodeGen output ordering changes, the PlistBuddy step still works because it copies fresh each run.
- **M3-01/M4-01 seam-name drift:** this issue names expected files but mandates discovery steps; if M3-01's middleware or M4-01's helper differ, adapt the call sites and record the actual names in the PR rather than duplicating code.
- **Probe endpoint semantics:** `/api/auth/info` answering 200-with-`user:null` (not 401) is load-bearing; if the server ever changes that, `SessionUserInfoDecodingTests` (fixtures) and the dead-token test fail first.
