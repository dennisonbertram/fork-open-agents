Binding decisions made by this issue (reconciliations a weak implementer must not re-derive). (a) Kind-symbol map: the §3.9 vocabulary has no glyph for Composio/dynamic tools or unknown parts; this issue extends it with `tool-composio → puzzlepiece.extension` and `unknown-part → questionmark.circle`, recorded by editing `docs/plans/ios-app/01-product-and-ux.md` §3.9 in the same PR (this issue is the design-review record). (b) Tool-name → kind mapping is total with a fallback: `read`/`grep`/`glob` → `.read`, `edit` → `.edit`, `write`/`todo_write` → `.write`, `bash` → `.shell`, `web_fetch` → `.fetch`, `task` → `.task`, every `dynamic-tool` part and every unrecognized `tool-<name>` (including `skill`, `ask_user_question`, `setup_managed_runtime_profile`, `propose_composio_tool`) → `.composio`. Never hardcode an exhaustive tool-name enum. (c) Group summary counts: `n` = tool parts in the group, `e` = parts of kind `.edit` or `.write`, `r` = parts of kind `.read`; zero-count segments are omitted; singular forms at 1 ("1 edit"). (d) The duration badge has no data source in persisted history (`GET /api/sessions/{sessionId}/chats/{chatId}` returns only `parts`, see `apps/web/app/api/sessions/[sessionId]/chats/[chatId]/route.ts:71`), so `MessageFooterBadges` takes `duration: Duration?` and hides the badge when nil; M7's live engine supplies it later. (e) `data-verified-build` and `data-runtime-proof` render as minimal labeled chips (status word from `data.status`), not their full web cards — no sibling owns the full cards; they are a later milestone.

## Why this matters

M6-05 ships a transcript that renders text, code, and reasoning — but real agent transcripts are dominated by tool calls and git data parts. A 50-tool run rendered naively is an unreadable wall; rendered per `01-product-and-ux.md` §5.4 it collapses to skimmable 44-pt rows under one "Ran 12 tools · 4 edits · 6 reads" header. This slice is also where the app earns P5's hard guarantee: every part type the server has ever persisted — including `dynamic-tool` parts from Composio tools the client has never heard of, and part types that do not exist yet — renders as something visible and tappable instead of a crash or a silent blank row. Finally it lands lesson B9: a bare "$0.34" cost badge erodes trust; the cost-context popover ("Estimated model cost for this reply. Session total: …") makes the number explainable. Without this issue the M6 verification checkpoint ("the transcript renders every part type" offline) cannot pass.

## User/operator path protected

P5 (`docs/plans/ios-app/06-testing-strategy.md` §2): tool calls, reasoning parts, file diffs, and data parts render correctly in the transcript. Concretely for this slice: a user opens a cached transcript whose messages contain every `UIMessagePart` type from `05-streaming-chat-engine.md` §1.6 — static tool parts in every state, `dynamic-tool` parts, `data-commit`/`data-pr`/`data-snippet`/`data-verified-build`/`data-runtime-proof`, and unknown part types — and sees no crash, no blank row, and no dropped part; tool errors are auto-expanded; footer badges explain cost on tap.

## Behavior contract

- Given a persisted assistant message with a `tool-bash` part in state `output-available` whose output is `{"stdout":"README.md\n","stderr":"","exitCode":0}`, When the transcript renders, Then a 44-pt collapsed row shows the `terminal` symbol, the command title from `input.command` in `Type.toolRow` (middle-truncated), and trailing `checkmark.circle.fill` in `StatusSuccess` with the word "Done" plus a disclosure chevron; When the user taps the row, Then it expands with `.snappy(duration: 0.2)` to show stdout in a mini code block (plain monospaced, copy enabled, no syntax highlight).
- Given a `tool-edit` part in `output-available` with `input.filePath`, `input.oldString` (3 lines), `input.newString` (5 lines), When expanded, Then the header shows `+5 −3` in `DiffAddedAccent`/`DiffRemovedAccent` and the body shows `newString` in a mini code block. (The "View diff" deep-link chip is out of scope — see below.)
- Given a tool part in state `output-error` with `errorText`, When the transcript renders, Then the row arrives **already expanded** showing `errorText` in the output block, with `xmark.circle.fill` in `StatusError` and the word "Failed". Status is always icon + word + color, never color alone.
- Given four consecutive tool parts (2 reads, 1 edit, 1 bash) with no non-tool part between them, When the transcript renders, Then they collapse under one summary header reading exactly "Ran 4 tools · 1 edit · 2 reads", rows hidden; When the header is tapped, Then all four rows toggle visible together. Given a single tool part between text parts, Then it renders as a bare row with no group header. Given a `reasoning` or `text` part interleaved, Then it breaks the group.
- Given a `dynamic-tool` part with `toolName: "GITHUB_CREATE_ISSUE"`, When rendered, Then the row uses the `puzzlepiece.extension` symbol, title "GITHUB_CREATE_ISSUE" (fall back to a ≤ 40-char excerpt of `input` JSON when `toolName` is somehow empty), and the same status chrome — with no tool-name enum lookup anywhere on the path.
- Given a tool part still in `input-streaming` or `input-available` in persisted history (stream closed while it ran) and `isStreaming == false`, Then the row shows `exclamationmark.triangle.fill` in `StatusWarning` with the word "Interrupted" — except `tool-ask_user_question` in `input-available`, which shows "Waiting" (it is the legitimate client-tool pause per `05-streaming-chat-engine.md` §1.5). Given `state == "output-denied"`, Then "Denied" in `StatusError`. Given `approval-requested`, Then "Waiting" in `StatusWarning` with no approval buttons (no approval UI in v1 per §1.5).
- Given a `data-commit` part with `data.status == "pending"`, Then an inline chip shows a spinner and "Committing…"; Given `{"status":"success","pushed":true,"commitSha":"9f8e7d6...","url":...}`, Then the chip shows the `arrow.triangle.branch` symbol (fallback `arrow.branch` if absent from SF Symbols), "Committed & pushed" and the 7-char short SHA, and tapping opens `url` in `SFSafariViewController`; Given `status == "error"`, Then "Commit failed" in `StatusError`; Given `"skipped"`, Then "Commit skipped" in secondary style. Same pattern for `data-pr`: "Creating pull request…" / "Opened PR #{n}" (`created == true`) / "Synced to existing PR #{n}" (`created == false`) / "Pull request failed" / "Pull request skipped". All payload fields decode all-optional; a chip with missing fields renders its status word and omits the detail, never crashes.
- Given a `data-snippet` part `{content, filename}` on a user message, Then a chip with the `doc.text` symbol and the filename (default "pasted-text.txt") renders; tap expands the content inline in a mini code block.
- Given a part whose `type` is unknown (e.g. `data-future-thing` or a malformed tool payload), Then a generic chip renders with the `questionmark.circle` symbol and the raw type string — the part is never dropped from the transcript — and `ui_unknown_part_rendered` is logged once per part id at notice.
- Given an assistant message whose `metadata.totalMessageCost == 0.0031` and `metadata.modelId == "anthropic/claude-haiku-4.5"`, Then the footer shows a cost badge "<$0.01" and a model pill "claude-haiku-4.5" in `Type.badge` (cost uses `.caption2.monospacedDigit()`); When the cost badge is tapped, Then a popover shows exactly "Estimated model cost for this reply. Session total: {sum}." where {sum} is the sum of `totalMessageCost` over all loaded messages in the chat, formatted the same way. Given `metadata` is nil or `totalMessageCost` is nil, Then the cost badge is absent (no "$0.00" noise). Given `duration == nil` (always true in M6), Then no duration badge.
- Given VoiceOver, Then each collapsed tool row is one element labeled "Tool: {Kind}, {title}, {status}." with expanded output exposed via `accessibilityCustomContent`; the group header is one element combining its summary copy with a hint "Double tap to expand"; chips and badges carry their visible text as labels.
- Given Dynamic Type AX3, Then no row clips or overlaps: 44 pt is a `minHeight`, never a fixed `frame(height:)`.

## Product and design spec

- Entry point: parts inside `TranscriptView`/`MessageRow` (M6-05, `ios/Packages/ChatFeature`). M6-05 leaves non-text/reasoning parts on a placeholder branch of its part dispatcher; this issue replaces that branch.
- Collapsed tool row anatomy (left → right): kind symbol (§3.9 map + binding decision (a)) · title `Type.toolRow`, `.truncationMode(.middle)` · trailing status (spinner `StatusRunning` while running / `checkmark.circle.fill` `StatusSuccess` "Done" / `xmark.circle.fill` `StatusError` "Failed"/"Denied" / `exclamationmark.triangle.fill` `StatusWarning` "Interrupted"/"Waiting") · `chevron.right` rotating on expand. Container: opaque `secondarySystemBackground`, `OARadius.card` (12), `minHeight: 44`, full row tappable via padded `.contentShape(Rectangle())`.
- Title per kind: `.read`/`.edit`/`.write` → `input.filePath`; `.shell` → `input.command`; `.fetch` → `input.url`; `.task` → `input.description` falling back to `input.prompt`; `.composio` → `toolName`. While `input` is absent (`input-streaming`), fall back to the tool name, then to a ≤ 40-char `rawInput` excerpt.
- Expanded output normalization (binding): output `JSONValue` renders as — string → plain text; object containing string `stdout`/`stderr` → stdout then a labeled stderr section; anything else → pretty-printed sorted-keys JSON. Cap displayed output at 10,000 characters with a trailing "Truncated" footnote. Mini code block = `CodeUI.CodeBlockView` with no language (no highlighting), copy enabled, its existing > 40-line collapse.
- Group header: `Type.timestamp` style summary text + chevron, same card container, one per run of ≥ 2 consecutive tool parts (`tool-*` and `dynamic-tool`; any other part type breaks the run). Default collapsed; expansion state keyed by group id (first `toolCallId`) lives in `ChatStore` so scrolling a `LazyVStack` does not reset it; per-row expansion keyed by `toolCallId` likewise.
- Data chips: one-line inline cards (`OARadius.chip`, hairline `CodeBorder` border) with leading symbol, status word, and optional detail; pending state shows a 16-pt `ProgressView`. Chips with a `url` get `.hoverEffect(.automatic)` and open `SFSafariViewController`.
- Footer badges row: under the last part of each assistant message — duration (hidden in M6) · cost · model pill, all `Type.badge`, secondary color. Cost format: `< 0.005` → "<$0.01", else "$" + two fraction digits. Model pill text: substring of `modelId` after the last "/", falling back to `selectedModelId`, hidden when both nil.
- Copy (exact strings): "Ran {n} tools · {e} edits · {r} reads" / "Done" / "Failed" / "Denied" / "Interrupted" / "Waiting" / "Running…" / "Committing…" / "Committed & pushed" / "Committed" / "Commit failed" / "Commit skipped" / "Creating pull request…" / "Opened PR #{n}" / "Synced to existing PR #{n}" / "Pull request failed" / "Pull request skipped" / "Truncated" / "Estimated model cost for this reply. Session total: {sum}."
- States: no loading/empty states of its own (the transcript owns those, M6-05); error state is the auto-expanded `output-error` row; offline changes nothing here (data is already local).
- Permissions: none.

## Observability and user feedback

Named module: `ChatFeature`, logging through the `EventLogging` seam into the `ui` category (`AppLog.ui`, subsystem = bundle id per `docs/plans/ios-app/07-observability.md` §3). Events (snake_case, §3.4 emitter):

- `ui_action` (info): `action` ∈ {`tool_row_expand`, `tool_row_collapse`, `tool_group_toggle`, `cost_badge_popover`, `data_chip_open_url`}, `screen="chat"`, `session_id`, `chat_id`. For tool events add `tool_kind` (the `ToolKind` raw value) — never the tool title.
- `ui_unknown_part_rendered` (notice): `part_type` (raw type string), `session_id`, `chat_id` — emitted once per part id per transcript load (deduplicate in the dispatcher). **New event**: add this row to the §4.5 table in `docs/plans/ios-app/07-observability.md` in the same PR.
- `ui_error_presented` is not used here (data-chip error states are persisted server outcomes, not client errors).

Typed error kinds: none new; chip URL opens that fail use the existing `cancelled`/system handling (no log above notice). Decode tolerance means malformed payloads surface as generic chips + `ui_unknown_part_rendered`, not `decode_failed` errors.

Correlation IDs: `session_id` and `chat_id` on every event (provided by `ChatStore`); no `request_id` (no network in this slice).

Redaction rules (binding, §7.3): tool titles, inputs, outputs, `errorText`, stdout, file paths, commit messages, snippet content, and SHAs are message content — **never logged at any level**. Loggable fields are exactly: event name, `action`, `screen`, `tool_kind`, `part_type`, `session_id`, `chat_id`, counts. The checklist's grep proof enforces this.

User-visible status: the tool-row status word + icon + color is itself the observability surface for run history; unknown parts are visibly chipped (never silently dropped), which is what makes a "my transcript is missing something" report falsifiable.

Debug recipes:

- Unknown-part audit on a booted simulator: `xcrun simctl spawn booted log show --last 30m --style compact --predicate 'category == "ui"' | grep ui_unknown_part_rendered` — shows which `part_type` values the server sent that this build has no renderer for.
- Interaction trace for a chat: `xcrun simctl spawn booted log show --last 30m --style compact --predicate 'category == "ui"' | grep '"chat_id".*<id>'` (or grep `chat_id=<id>` for key=value lines).

## Regression risks and concerns

- **Hardcoded tool-name enum creep**: an implementer may "tidy" the mapping into an exhaustive enum that throws on unknown names — that breaks every future server tool and all Composio tools. Test 1's arbitrary-name cases pin the fallback.
- **Dropped unknown parts**: filtering unrenderable parts out of the array would also break M6-04's round-trip echo-back guarantee (the same array is POSTed back). This issue renders from the model and never mutates it; test 6 plus M6-04's round-trip suite pin both sides.
- **Content leakage into logs**: tool titles/outputs are message content; one careless interpolation violates §7.3. The grep proof and the restricted field list are the guard.
- **AX3 clipping**: `frame(height: 44)` instead of `minHeight` truncates AX3 text; the ax3 snapshot catches it.
- **Color-only status**: trailing icon without the status word fails the §5.4 invariant and Differentiate Without Color; snapshot + test 2's label assertions pin icon + word.
- **Group miscount with interleaved parts**: counting `step-start` or `reasoning` as group members corrupts the summary; test 3's split cases pin the boundary (only `tool-*`/`dynamic-tool` group).
- **Expansion state loss in `LazyVStack`**: per-row `@State` resets on recycle; state lives in `ChatStore` keyed by `toolCallId`/group id instead.
- **Huge outputs**: pretty-printing a multi-megabyte task output on the main thread can hitch scrolling; the 10,000-char cap is applied during `ToolPartViewState` construction, not in `body`.
- **Snapshot nondeterminism**: any `Date()`, live image, or animation in the fixture view flakes CI; §6.4 hygiene checklist applies.
- **M6-05 interface drift**: if the dispatcher or `ChatStore` shapes differ from this plan, adapt to what shipped and record the delta — do not fork a second dispatcher.
