## Why this matters

Every M6 surface — the cache-first sessions inbox (M6-02), offline-readable transcripts (M6-05), chat history caching (M6-04) — renders from GRDB before the network answers. This issue builds that floor: `ios/Packages/PersistenceKit` migration v1 with all eleven tables, the cache APIs with `ValueObservation` AsyncSequences, the `nuke()` escape hatch wired to sign-out, the account-id-mismatch guard, and launch pruning. Without it, M6-02 through M6-06 have nowhere to read from on cold launch, offline mode is a blank screen, and a second account signing in on the same device would see the first account's cached sessions — a privacy defect, not just a bug. The design deliberately treats the cache as disposable (raw JSON blob + a few indexed columns; server is the source of truth), so server field additions never need a client schema migration and `nuke()` + re-sync is always a safe recovery.

## User/operator path protected

P9 (`docs/plans/ios-app/06-testing-strategy.md` section 2) — offline or degraded network shows cached sessions/transcripts with explicit staleness, never a blank crash. Concretely for this slice: cached rows written through the cache APIs survive process relaunch (file-backed DB round-trip), and sign-out or signing in with a different account id provably deletes every cached row before any new write. Secondary: the launch path never grows unboundedly — transcript and repo caches are pruned on every launch.

## Behavior contract

- Given a fresh install (no database file), when `AppDatabase.open(at:)` runs, then migration `v1` is applied, exactly eleven tables exist (`session`, `chat`, `chatMessage`, `repo`, `githubInstallation`, `inferenceProfile`, `userPreferences`, `userProfile`, `chatDraft`, `syncState`, `appMeta`), the four declared indexes exist (`chat.sessionId`, `chatMessage.chatId`, `repo.installationId`, `session.lastActivityAt`), and `db_opened` is logged at notice with `schema_version=v1`.
- Given sessions written via `sessions.replaceAll(_:)` into a file-backed database, when the `AppDatabase` is closed and a new `AppDatabase.open(at:)` is created at the same URL, then the same rows are read back (P9 relaunch survival).
- Given a cached `session` row whose `detailJson`/`detailFetchedAt` were filled by `upsertDetail(_:)`, when `replaceAll(_:)` runs with a list that still contains that session id (with changed `title`/`hasUnread`), then the list columns are updated and `detailJson`/`detailFetchedAt` are untouched.
- Given cached sessions A, B, C with chats and chat messages under B, when `replaceAll([A, C])` runs, then session B's row is deleted and the FK cascade removes its `chat` and `chatMessage` rows in the same transaction, and `syncState["sessions"].lastRefreshedAt` is updated.
- Given an active `observeAll()` AsyncSequence on any cache, when a write changes the observed rows, then a new array is emitted on the sequence; when a write produces byte-identical content (same rows re-written), then no duplicate emission occurs (`removeDuplicates`).
- Given any populated database, when `nuke()` runs, then all rows in all eleven tables are deleted in one transaction (including `appMeta`) and `db_cache_reset` is logged at notice with `reason=user_signout`.
- Given the AppShell wiring, when `AuthController.signOut()` completes, then the `auth.onSignedOut` hook fires `db.nuke()` and a subsequent read of any cache returns empty (P9 wipe proof).
- Given `appMeta["accountUserId"] == "user-a"` and populated caches, when `ensureAccount(userId: "user-b")` runs, then every row is deleted first, `appMeta["accountUserId"]` becomes `"user-b"`, the call returns `.switchedAccountNuked`, and `db_cache_reset` is logged with `reason=account_mismatch`. When called with `"user-a"`, nothing is deleted and it returns `.matched`. On first launch (no stored id) it stores the id and returns `.firstLaunch`.
- Given 51 chats each having `chatMessage` rows, when `pruneOnLaunch()` runs, then the `chatMessage` rows of the single least-recently-updated chat (lowest `chat.updatedAt`) are deleted, the other 50 chats' messages are intact, and all 51 `chat` rows remain. Given `repo` rows with `fetchedAt` 8 days old and 6 days old, then only the 8-day-old row is deleted. `db_prune_finished` is logged with the counts.
- Given `transcripts.replaceMessages(chatId:_:)` with N messages, when it completes, then exactly N rows exist for that chat with `position` values `0...N-1` matching array order, prior rows for that chat are gone, other chats' rows are untouched, and `messageJson` reads back byte-identical to what was written. An empty array clears the chat's rows (edge case).
- Given a release (non-DEBUG) build where `migrator.migrate()` throws on open, when `AppDatabase.open(at:)` handles it, then it logs `db_migration_failed` at fault, deletes the database file (plus `-wal`/`-shm` siblings), re-creates and re-migrates once, and logs `db_cache_reset` with `reason=corruption`; if the retry also throws, the error propagates (error case). In DEBUG builds, `eraseDatabaseOnSchemaChange = true` handles schema churn instead and genuine failures rethrow.
- Given `appMeta["schemaSentinel"]` holds a value other than `"v1"` after migration (downgrade edge case), when open completes, then the rows are nuked with `reason=schema_mismatch` and the sentinel is rewritten to `"v1"`.

## Product and design spec

No screen ships in this slice; the product surface is behavioral and proven by tests plus the M6 checkpoint smoke. Entry points: app launch (`AppDatabase.open` + `ensureAccount` + `pruneOnLaunch` in AppShell), sign-out (`auth.onSignedOut` → `nuke()`), and every cache read/write issued by later M6 stores. User-visible consequences this slice must make true: (1) cold launch can render cached data instantly with no spinner once M6-02 lands; (2) signing out and handing the device to someone else leaves zero cached sessions, transcripts, drafts, or preferences; (3) the app's disk footprint stays bounded (50 recent chats of transcript cache, 7-day repo cache). Loading/empty behavior: caches return empty arrays/`nil` on a fresh or nuked database — never throw for "no data". Error behavior: write failures throw to the calling store (M6-02+ owns user-facing error copy); this package logs and rethrows. Copy: none. Accessibility: not applicable. Permissions: none — the database lives in the app sandbox at `Application Support/OpenAgents/openagents.sqlite` with file protection `.completeUntilFirstUserAuthentication`.

Indexes: `try db.create(indexOn: "chat", columns: ["sessionId"])`, `try db.create(indexOn: "chatMessage", columns: ["chatId"])`, `try db.create(indexOn: "repo", columns: ["installationId"])`, `try db.create(indexOn: "session", columns: ["lastActivityAt"])`. GRDB column types: `.text`/`.integer`/`.boolean`/`.datetime` map 1:1 to the table above. FK example: `t.column("sessionId", .text).notNull().references("session", onDelete: .cascade)`. Composite PK: `t.primaryKey(["chatId", "id"])`; unique: `t.uniqueKey(["chatId", "position"])`; singleton check: `t.check(Column("id") == 1)`.

Public API (normative; domain models `Session`, `SessionDetail`, `Chat`, `Repo`, `GitHubInstallation`, `InferenceProfile`, `UserPreferences`, `UserInfo` come from `OpenAgentsCore` per M3-02 — add `Equatable` conformance there if any is missing, observation dedupe requires it):

```swift
public enum CacheResetReason: String, Sendable {
  case userSignout = "user_signout", accountMismatch = "account_mismatch"
  case schemaMismatch = "schema_mismatch", corruption = "corruption"
}
public enum AccountGuardOutcome: Equatable, Sendable { case firstLaunch, matched, switchedAccountNuked }

public final class AppDatabase: Sendable {
  public static func open(at url: URL) throws -> AppDatabase     // DatabasePool, WAL, migrate, sentinel check, release-mode recovery
  public static func inMemory() throws -> AppDatabase            // DatabaseQueue; tests + previews
  public static func defaultURL() throws -> URL                  // Application Support/OpenAgents/openagents.sqlite (creates the directory)
  public func nuke(reason: CacheResetReason = .userSignout) async throws   // delete all rows, all 11 tables, one transaction
  public func ensureAccount(userId: String) async throws -> AccountGuardOutcome
  public func pruneOnLaunch() async throws                       // internal prune(now:) seam for tests; constants 50 chats / 7-day repos

  public var sessions: SessionCache { get }
  public var chats: ChatCache { get }
  public var transcripts: TranscriptCache { get }
  public var repos: RepoCache { get }
  public var profiles: ProfileCache { get }
  public var preferences: PreferencesCache { get }
  public var drafts: DraftStore { get }
  public var syncState: SyncStateStore { get }
}

public struct SessionCache: Sendable {
  public func replaceAll(_ sessions: [Session]) async throws            // delete absent ids (cascades), update-or-insert present ones WITHOUT touching detailJson/detailFetchedAt, touch syncState["sessions"]
  public func upsertDetail(_ detail: SessionDetail) async throws        // write detailJson (encoded SessionDetail) + detailFetchedAt = now + refresh list columns
  public func observeAll() -> some AsyncSequence<[Session], any Error>  // ordered lastActivityAt DESC; ValueObservation + removeDuplicates
  public func observeDetail(id: String) -> some AsyncSequence<SessionDetail?, any Error>
}
public struct ChatCache: Sendable {
  public func replaceAll(sessionId: String, _ chats: [Chat]) async throws  // scoped: deletes absent ids for THAT session only; touch syncState["chats:<sessionId>"]
  public func upsert(_ chat: Chat) async throws
  public func observeAll(sessionId: String) -> some AsyncSequence<[Chat], any Error>  // createdAt ASC
}
public struct PersistedMessage: Equatable, Sendable {                    // M6-04 maps UIMessage ↔ this; messageJson is opaque verbatim JSON here
  public let id: String; public let role: String
  public let messageJson: String; public let createdAt: Date?
}
public struct TranscriptCache: Sendable {
  public func replaceMessages(chatId: String, _ messages: [PersistedMessage]) async throws  // one transaction: delete chat's rows, insert with position = array index; touch syncState["messages:<chatId>"]
  public func messages(chatId: String) async throws -> [PersistedMessage]                   // ordered by position
  public func observeMessages(chatId: String) -> some AsyncSequence<[PersistedMessage], any Error>
}
public struct RepoCache: Sendable {
  public func replaceAll(installationId: Int, _ repos: [Repo]) async throws  // scoped per installation; sets fetchedAt = now; touch syncState["repos:<installationId>"]
  public func observeAll() -> some AsyncSequence<[Repo], any Error>
}
public struct ProfileCache: Sendable {
  public func replaceInferenceProfiles(_ profiles: [InferenceProfile]) async throws  // json column = encoded model; fetchedAt = now
  public func replaceInstallations(_ installations: [GitHubInstallation]) async throws
  public func observeInferenceProfiles() -> some AsyncSequence<[InferenceProfile], any Error>
  public func observeInstallations() -> some AsyncSequence<[GitHubInstallation], any Error>
}
public struct PreferencesCache: Sendable {
  public func setPreferences(_ prefs: UserPreferences) async throws     // singleton row id = 1
  public func observePreferences() -> some AsyncSequence<UserPreferences?, any Error>
  public func setUserProfile(_ user: UserInfo) async throws             // singleton row id = 1
  public func observeUserProfile() -> some AsyncSequence<UserInfo?, any Error>
}
public struct DraftStore: Sendable {
  public func draft(chatId: String) async throws -> String?
  public func setDraft(chatId: String, text: String) async throws       // empty/whitespace-only text deletes the row
  public func deleteDraft(chatId: String) async throws
}
public struct SyncStateStore: Sendable {
  public func lastRefreshedAt(collection: String) async throws -> Date?
  public func touch(collection: String) async throws
}
```

Implementation notes (load-bearing): `replaceAll` runs in one `writer.write` transaction — delete absent ids via `filter(!ids.contains(Column("id"))).deleteAll(db)`, then per row: if the PK exists, `updateAll(db, ...)` with explicit `ColumnAssignment`s for the list columns only (never `detailJson`/`detailFetchedAt`); else `insert(db)`. Observations are built as `ValueObservation.tracking { db in /* fetch + map to domain models */ }.removeDuplicates().values(in: reader)` and returned as opaque AsyncSequences. JSON blob columns (`detailJson`, `json`, `messageJson`) encode/decode with the ISO-8601 fractional-seconds helpers from `OpenAgentsCore` (M3-02); `messageJson` is stored and returned verbatim — PersistenceKit never re-encodes it. "50 most recently active chats" = top 50 by `chat.updatedAt DESC`; pruning deletes only `chatMessage` rows of chats outside that set (chat rows stay). `ensureAccount` must be awaited before any cache write on launch. Cache writes wrap GRDB errors with a `db_write_failed` log (entity + op) and rethrow.

- `db_migration_started` notice `{ from_version ("none" on fresh install), to_version="v1" }`

- `db_migration_failed` fault `{ from_version, to_version, error_kind=db_migration_failed }`

## Regression risks and concerns

- Known cross-doc delta: `docs/plans/ios-app/05-streaming-chat-engine.md` section 6.2 sketches a `chat_message` table with `sync_state`/`updated_at_local` columns and a single-column PK. The architecture doc section 9.3 (this issue's normative source) supersedes the naming and column list for v1; M6-04 owns reconciling the outbox columns and may edit migration `v1` in place pre-release. Do not add those columns speculatively here.
- `removeDuplicates` requires `Equatable` domain models; a missing conformance surfaces as a compile error in this package — fix in `OpenAgentsCore`, never by dropping the dedupe.
- GRDB API drift: the issue pins 7.11.0; if `create(indexOn:columns:)`, `uniqueKey`, `updateAll`, or `values(in:)` do not resolve, consult GRDB 7 docs via `ctx7` rather than approximating with raw SQL (raw SQL is acceptable only where GRDB has no API, and must be commented).
- Accidental `detailJson` clobbering is the highest-value regression this slice guards: any future refactor of `replaceAll` toward whole-row `upsert` will silently wipe details and only `replaceAllPreservesDetailJsonAndDetailFetchedAt` will catch it. Keep that test strict (assert byte-equality of the stored blob).
- In-memory `DatabaseQueue` vs file `DatabasePool` behavior differences (WAL, snapshots) — observation tests run on both paths via `RelaunchPersistenceTests` to keep `inMemory()` honest as a test double.
- Parallel Swift Testing: every test must own its database instance; a shared temp path would flake. `RelaunchPersistenceTests` must generate a unique directory per test (`UUID().uuidString`).
- The AppShell edit lands in a file other milestones also touch; keep the wiring diff to the lines specified to avoid merge friction with M6-02's store registration.
- `ensureAccount` ordering: if a future bootstrap refactor starts store refreshes before the guard resolves, a fast network response could write user-b data pre-nuke. The behavior contract pins "nuked before any write"; M6-02's store activation must stay sequenced after it (call this out in the PR description for the M6-02 implementer).
